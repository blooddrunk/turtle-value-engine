## 8. READY_FOR_OWNER_AUTHORIZED_LIVE_ACCEPTANCE

The offline implementation is complete, but live acceptance cannot be honestly
claimed because these owner-specific inputs are absent from the execution
environment:

1. Cloudflare account ID and an API token with the minimum Worker Scripts,
   Access Apps/Policies, Access Service Tokens, Tunnel and DNS permissions.
   Codex cannot infer the account or authorize a token. Provide them through
   `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` in the owner-approved
   secret manager/environment; never paste the token into chat or commit it.
2. Owner-selected `TVE_DASHBOARD_HOSTNAME`,
   `TVE_SURFACE_ORIGIN_HOSTNAME`, `TVE_SURFACE_API_ORIGIN` (HTTPS), zone ID,
   existing Tunnel ID or an explicit Tunnel name, and the approved
   `TVE_DASHBOARD_ACCESS_EMAIL`. These are DNS/account/identity facts, not
   derivable repository values. Provide them as non-secret environment values.
3. A host authorized to run `tve surface serve` and `cloudflared`, plus an
   explicit `TVE_SURFACE_SNAPSHOT_PATH`. The origin host/path is owner state;
   provide the path through the environment or `--snapshot`, with the M6-B
   process bound to `127.0.0.1` only.
4. Two service-token pairs: `SURFACE_API_ACCESS_CLIENT_ID` /
   `SURFACE_API_ACCESS_CLIENT_SECRET` for Worker → origin and
   `TVE_DASHBOARD_ACCESS_CLIENT_ID` /
   `TVE_DASHBOARD_ACCESS_CLIENT_SECRET` for automated Dashboard smoke. Store
   them in the secret manager/environment only. The deployment script accepts
   an explicit origin-token create flag when the API token has permission, but
   it never prints or commits the one-time secret.

Once those references exist, Codex will run exactly:

```bash
python3 scripts/dashboard_deploy.py preflight
python3 scripts/dashboard_deploy.py deploy --dry-run
python3 scripts/dashboard_deploy.py deploy --apply
python3 scripts/dashboard_deploy.py verify
python3 scripts/dashboard_live_smoke.py
```

The deploy command automatically builds the exact checkout, checks Wrangler,
creates/updates only the named Access apps, remote Tunnel ingress, origin CNAME
and Worker secrets, verifies workers.dev/preview/custom-domain/bypass state,
and records only non-sensitive resource IDs/hostnames. The origin host runs:

```bash
python3 scripts/dashboard_deploy.py origin \
  --snapshot "$TVE_SURFACE_SNAPSHOT_PATH" \
  --port "${TVE_SURFACE_PORT:-8787}"
```

The live smoke then proves unauthenticated Dashboard/origin blocking and the
authenticated Dashboard → Worker → HTTPS origin → M6-B chain, including
health, list, known detail identity/hash, 404, mutation 405 and ETag 304.

Not yet passed, solely because of the missing inputs: live Cloudflare Worker
deployment, Access policies, Tunnel connector/ingress reachability, origin
unauthenticated blocking, authenticated live surface reads, alternate-route
checks against the real account, and the owner interactive IdP check.

After automated live smoke passes, the only remaining human acceptance is the
goal-defined incognito browser check: Access wall before Dashboard, approved
