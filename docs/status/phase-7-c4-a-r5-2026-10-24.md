## 3. Minimal repair

`src/turtle_value_engine/evolution/activation_execution.py` only (24 added
lines, 5 replaced):

1. `_load_verified_before_image`: the bare `tomllib.loads(...decode())` is
   wrapped in `except (tomllib.TOMLDecodeError, UnicodeDecodeError)` → the
   established named `ActivationExecutionError("BEFORE_IMAGE_CONTENT_MISMATCH")`
   (the same classification the C4-B status inspector
   `activation_status._verify_before_image` already reports for identical
   bytes), and the nested `.get` is replaced by an `isinstance(dict)` guard
   before reading `default`. No blanket `except Exception`; hashes, receipt
   identities, locking, journal/outcome order and every existing outcome
   are untouched.
2. `rollback_profile_activation` idempotence branch: the unguarded nested
   `.get` over the *current* bytes is replaced by the new private helper
   `_prior_default_in_place()`, which answers the same question
   structurally: bytes that do not decode/parse as UTF-8 TOML, or whose
   `profiles` is not a table holding the receipt's prior default, do not
   *prove* the prior default in place, so the executor falls through to its
   existing hash-precondition refusal — the established blocked status
   `ROLLBACK_PRECONDITION_VIOLATED` (CLI exit class 1) with
   current/expected hashes, zero config clobber and zero rollback-intent or
   outcome writes. **No new error code was added for this case**: the
   pre-existing blocked class is the exact semantic for "the current config
   does not hold what this receipt needs", and the goal's "match existing
   error semantics where possible" branch applies. Genuine receipts are
   unaffected (a real prior config parses as a dict-`profiles` TOML), so
   normal apply/rollback idempotence semantics are byte-identical.
