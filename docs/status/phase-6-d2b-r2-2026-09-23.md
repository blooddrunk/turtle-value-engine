## Delivered boundary

R2 changes only the retry-budget accounting / crash-recovery state machine
of the D2B delivery ledger. D1, D2A/R1, Phase 6-A/6-B/6-C, `strict-v1`,
valuation, hard gates, monitoring cursors, re-analysis, webhook payload
meaning, the deterministic `delivery_id`/`Idempotency-Key`, R1 flock
single-flight semantics, the R1 overall monotonic HTTP deadline, R1
read-only pointer-status truthfulness, and the secret/network boundaries are
untouched. No persisted contract field changed; the two checked-in delivery
schemas were regenerated with description-only diffs (contract fields are
byte-identical).

The correctness invariant is now structural:

> **The durable `MonitoringDispatchClaimV1` set `1..N` of one `delivery_id`
> IS the retry-budget ledger.** Every claim — persisted before the transport
> may write any request byte — consumes exactly one `max_attempts` position
> whether or not its `MonitoringDeliveryAttemptV1` outcome ever became
> durable. `max_attempts` is therefore a hard upper bound on authorized
> outbound transport entries across the entire durable ledger lifetime,
> including dispatches whose process died between the claim and the
> attempt-outcome save.

- **Budget from durable dispatch evidence, not `len(attempts)` (F5).**
  `derive_delivery_state` now derives remaining budget from the durable
  claim set (`consumed = len(claims)`). Claims above every persisted attempt
  (tail orphans) mean a prior process may have dispatched and died: the
  delivery is post-dispatch uncertain — terminal
  `AMBIGUOUS`/`ORPHANED_DISPATCH` unless `receiver_idempotency_declared`
  **and** a budget slot remain. An unresolved claim below a later persisted
  attempt is *superseded* by that outcome (it no longer forces `AMBIGUOUS`)
  but still consumes budget. Retry-exhaustion of completed retryable
  attempts is likewise decided by consumed slots, and an `AMBIGUOUS` outcome
  with a scheduled receiver-idempotent retry becomes terminal once the
  budget is gone. Nothing fabricates an HTTP outcome, response status,
  timestamp or proof of delivery; an orphan stays post-dispatch uncertain.
- **New monotonic slot per transport entry.** `_deliver_locked` allocates
  slot `len(claims) + 1` for every new outbound transport entry and
  `_perform_attempt` persists that NEW claim before the request may be
  written (plus a defense-in-depth refusal if the slot would exceed
  `max_attempts`). An orphaned claim is never reused as a budget token for
  another request; the receiver-facing `Idempotency-Key` stays the same
  deterministic `delivery_id`. Because slot numbering now follows durable
  claims, the attempt set may legitimately contain gaps (an orphan slot
  skipped by a later retry); each attempt keeps its dispatch-slot number.
- **Fail-closed recovery validation.** The new
  `validate_dispatch_evidence(intent, attempts, claims)` (replacing
  `unresolved_dispatch_claim`) runs before any state derivation, repair or
  transport entry and rejects: more durable slots than the configured
  maximum; any claim (not only the unresolved one) not bound to this
  intent/payload; and any attempt outcome whose durable dispatch slot is
  missing. The store keeps claims strictly contiguous from one (a skipped
  budget position is contradictory) while allowing the attempt set its
  legitimate gaps. Recovery stays deterministic from immutable artifacts —
  no mutable retry counter was introduced.
- **Default non-idempotent policy unchanged.** An orphaned dispatch under
  `receiver_idempotency_declared=false` remains terminal `AMBIGUOUS` with
  zero automatic resend; multiple unresolved claims inside the budget (the
  legitimate repeated-crash state) stay conservatively terminal
  `AMBIGUOUS` instead of raising.
- **Additive status projection.** `delivery_status_projection` /
  `tve watch delivery-status` add `unresolved_claim_numbers` (all
  unresolved slots) next to the existing `dispatch_claim_count` and
  `unresolved_dispatch_claim` (now the highest tail orphan); the projection
  validates evidence through the same fail-closed validator.

Goal findings → automatic evidence:

- **max_attempts=1 + declared receiver idempotency + orphaned claim 1**:
  `test_r2_max_attempts_one_orphan_restart_sends_zero` — crash after durable
  claim / possible dispatch before attempt save; restart performs ZERO new
  transport calls (a crashing guard transport proves it by construction)
  and exposes terminal `AMBIGUOUS`/`ORPHANED_DISPATCH`; exactly one
  transport entry ever happened in the ledger's lifetime.
- **repeated crash loop bounded**: `test_r2_repeated_crash_after_dispatch_loop_is_bounded`
  — `max_attempts=3`, every permitted wake dies after durable dispatch
  evidence and before attempt-outcome persistence; three wakes each enter
  transport exactly once (claims 1,2,3), every later wake performs zero and
  reports terminal `AMBIGUOUS`; total transport entries never exceed 3 and
  the projection reports `dispatch_claim_count == 3`,
  `unresolved_claim_numbers == [1, 2, 3]`.
- **new monotonic slot before transport, key unchanged**:
  `test_r2_recovery_retry_persists_new_slot_before_transport` — a
  slot-aware transport records the durable claim set at send time: the
  recovery retry saw slots `[1, 2]` durable before its request, never
  reusing slot 1, with the byte-identical receiver idempotency key.
- **shared budget, no double spend / no skip**:
  `test_r2_completed_attempts_and_orphan_slots_share_one_budget` — a
  completed retryable attempt (slot 1), an orphaned slot 2 and a successful
  recovery slot 3 consume exactly the three positions of a
  `max_attempts=3` budget; final state `DELIVERED`, attempt set `[1, 3]`,
  claim set `[1, 2, 3]`, three total transport entries, identical keys.
  `test_orphaned_claim_retries_only_under_declared_receiver_idempotency`
  proves the same boundary end-to-end including the untouched orphan claim
  bytes, and `test_orphaned_claim_with_exhausted_budget_stays_terminal_ambiguous`
  derives the F5 unit cases (claim-1-only under `max_attempts=1` terminal;
  one slot remaining under `max_attempts=3` pending; third slot terminal).
- **non-idempotent zero-resend unchanged**:
  `test_crash_after_claim_before_send_is_conservative_ambiguous_zero_resend`,
  `test_crash_after_possible_dispatch_before_outcome_save_is_ambiguous` and
  the legitimate multi-orphan branch of
  `test_unresolved_claim_conflicts_fail_closed` all stay green.
- **contradictory evidence fails closed before transport**:
  `test_unresolved_claim_conflicts_fail_closed` — over-budget claim count
  (`exceed the configured retry budget`), non-monotonic/gapped claim
  sequence (`contiguous from one`), an attempt outcome without its durable
  dispatch slot (`no durable dispatch slot`) and a foreign-bound claim (`not
  bound to this intent`) each raise `DeliveryLedgerConflictError` with zero
  transport calls.
- **all prior D2B/R1 boundaries stay green**: the remaining 59 pre-R2
  delivery cases (crash windows, two-process flock single-flight barrier,
