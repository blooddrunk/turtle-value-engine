## The invariant and how it is enforced

For every accepted non-secret owner input that reaches a generated artifact:

    typed owner input -> rendered systemd/TOML bytes -> real parser (systemd
    manager / tomllib) -> effective value == typed value exactly

R4 replaces the pre-R4 shell-oriented serialization (`shlex.join()` for the
`ExecStartPre=` gate line, raw string interpolation for `ExecStart=` and the
path directives, raw TOML basic-string interpolation) with one explicit
systemd-native serialization boundary plus a TOML-safe encoder, all in
`scripts/monitoring_production_ops.py`:

1. **Exec command lines** (`ExecStartPre=` gate, `ExecStart=` main):
   `systemd_exec_argument()` serializes each argv element per the
   systemd.syntax(7) quoting grammar — backslashes doubled, a double quote
   escaped, whole-item double quotes when the element contains
   tokenizer-active characters — and doubles every literal `$` and `%`
   because both expansions stay active *inside* quotes (`$$`/`%%`).
   `systemd_exec_command()` joins the elements; ordinary tokens serialize to
   themselves, so ordinary rendering stays byte-identical. `shlex` remains
   reserved for the human-facing shell resume commands only.
2. **Path/text directives**: `EnvironmentFile=`/`WorkingDirectory=` values
   are emitted with percent doubling only (quoting is not supported there —
   quotes would become literal path bytes; spaces/quotes/dollar/semicolon/
   hash/non-ASCII stay raw); the `Description=` runner id and the
   `Documentation=` file URL (URL-encoded, then percent-doubled) get the
   same percent protection. `OnCalendar=` stays verbatim by design.
3. **Render-boundary parity self-check**: `render_service_unit()` mirror-
   parses its own serialized lines through `parse_systemd_exec_command()` /
   `effective_unit_path_value()` and requires the effective values to equal
   the intended argv/paths before any unit bytes leave the function.
   `main_exec_argv()` is the single definition of the intended main command
   shared by the renderer and the verification.
4. **Generated project TOML**: `toml_basic_string()` is a real TOML
   basic-string encoder (quote/backslash escapes, short control escapes,
   `\uXXXX` for other control characters, raw Unicode otherwise);
   `render_project_config()` routes every owner-provided string through it
   and proves `tomllib.loads()` returns every typed owner value exactly
   before returning the text.
5. **Structural manager-effective verification**: `cmd_verify` now queries
   the exact manager-loaded argv arrays through
   `busctl --json=short get-property ... Service ExecStart/ExecStartPre`
   (plus `EnvironmentFiles` paths) and compares them element-by-element with
   `credential_gate_argv(config)`/`main_exec_argv(...)`/the typed credential
   path. The pre-R4 substring checks (`expected_exec in ExecStart`,
   `expected_gate in ExecStartPre`) are gone: a substring cannot represent
   argument boundaries. The new additive check names are
   `service.effective-execstart`, `service.prestart-gate` (delivery-enabled:
   exact gate argv; delivery-disabled: zero pre-start commands) and
   `service.effective-environmentfile`; verify stays non-mutating.
6. **Parse-time fail-closed narrowing of the genuinely unrepresentable**:
   control characters are now rejected for every unit-serialized owner field
   (`python_executable`, `working_directory`, `production_root`,
   `runner_id`, alongside the existing `delivery_environment_file` rule);
   `python_executable` — the only owner-controlled Exec *executable* token —
   additionally rejects `'`, `"`, `\`, `$` which systemd refuses or cannot
   prove literal in that position; the delivery environment-file path
   rejects backslashes. Ordinary filesystem characters (spaces, quotes,
   dollar, percent, semicolon, hash, non-ASCII) remain accepted everywhere
   they are representable, per goal section 5.

No credential value or credential-derived digest/fingerprint exists in any
rendered unit, generated config, test fixture or recorded artifact; the
serialization layer handles non-secret owner inputs only.

## systemd grammar facts (empirically established against systemd 259)

The serializer design was validated against the real user manager on this
host (load-time `busctl` argv arrays, runtime argv dumps through a helper,
and real `EnvironmentFile=`/`WorkingDirectory=` resolution):

- Exec tokenization follows systemd.syntax(7): whole-item `"`/`'` quoting
  with C-style escapes; `\"` works inside and outside quotes; `;`/`#` are
  ordinary data (a standalone `;` argument is wrapped by the serializer).
- `$VAR`/`${VAR}` expand at *execution* time (positive control: unescaped
  `$MYVAR` reached the process as its value) and `$$` restores a literal
  dollar; `%%` restores a literal percent while raw `%n` expands to the
  unit name. Neither expansion is disabled by quoting.
- `EnvironmentFile=`/`WorkingDirectory=` do not support quoting; spaces,
  quotes, `$`, `;`, `#` and non-ASCII round-trip raw; `%%` doubling restores
  literal percent in both at execution time (a real env file named
  `per%cent.env`/`spec%nname.env` was loaded from the `%%`-escaped path).
- A backslash in the `EnvironmentFile=` path is *unrepresentable*: the
  exec-time loader treats it as an escape (the literal file is never found,
  raw or doubled) — hence the parse-time rejection. `WorkingDirectory=`
  treats backslashes as ordinary data (verified with a real `\` directory).
- The Exec executable token (argv[0]) refuses `'`, `"`, `\` ("Executable
  path contains special characters" is a fatal load error under
  `systemd-analyze verify`); a space-bearing executable is accepted when
  quoted and executes correctly at runtime — hence the parse-time rejection
  set for `python_executable` and the space-only interpreter directory in
  the transient proof.
- `Description=` expands specifiers and `Documentation=` collapses `%%` and
  splits on spaces (URL list) — hence percent doubling and URL encoding
  there.
