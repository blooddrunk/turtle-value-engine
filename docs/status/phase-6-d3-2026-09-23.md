## Delivered boundary

D3 observes the already-proven Phase 6 monitoring runtime; it adds no runtime
authority. D1, D2A/R1, D2B/R1/R2, Phase 6-A/6-B/6-C, `strict-v1`, valuation,
hard gates, monitoring cursors, re-analysis semantics, the webhook payload
contract, the secret/network boundaries and every persisted monitoring
contract are untouched.

The delivered slice is one versioned, framework-neutral, secret-free read
model plus thin HTTP/Worker/UI shells:

- `src/turtle_value_engine/monitoring_operations/` — typed
  `MonitoringOperationsSourcesV1` (exactly one `RunnerConfigV1` plus the
  optional typed `[monitoring.delivery]` `delivery_root`; no recursive
  scanning, no guessed paths, no remote state), the
  `MonitoringOperationsProjectionV1` contract, the read-only projection
  builder and the read service. One projection covers exactly one configured
  chain: `MonitoringWorkspace` status, `RunnerStore`/`RunnerLease` read-only
  state (`RunnerLease.probe()`), the active activation (otherwise the latest
  terminal one), that activation's D1 cycle, only the re-analysis jobs that
  cycle references, and only the D2B deliveries bound to that activation via
  the non-repairing `delivery_status_projection` read path. Local roots,
  endpoint/auth secrets, lease holder tokens and raw response bodies are
  structurally excluded; fail-closed errors expose only stable codes and
  exception type names.
- `schemas/monitoring-operations-projection.schema.json` — checked in and
  drift-tested.
- `src/turtle_value_engine/surface/api.py` — additive
  `GET /v1/monitoring/operations` behind an optional monitoring service:
  typed generated response, `Cache-Control: no-store`, query parameters
  rejected (400), every mutation verb rejected (405
  `READ_ONLY_METHOD_NOT_ALLOWED`), unknown subpaths fail closed (404
  `MONITORING_OPERATIONS_NOT_FOUND`), contradictory store evidence fails
  closed (409 `MONITORING_OPERATIONS_CONFLICT`) without local-path or secret
  leakage. Surface-only app construction is unchanged.
- `src/turtle_value_engine/cli.py` — `tve surface serve` gains
  `--monitoring-runner-config` (required for monitoring) and
  `--monitoring-project-config` (optional `delivery_root` source; requires
  the runner config).
- `schemas/research-surface-api-v1.openapi.json` +
  `apps/dashboard/src/generated/surface-api.d.ts` — regenerated,
  drift-checked (`scripts/export_surface_openapi.py --check`,
  `pnpm api:check`, `pnpm types:check`).
- `apps/dashboard/worker/index.ts` — the allowlist gains exactly one fixed
  route, `/api/v1/monitoring/operations`; Access service credentials remain
  server-side only.
- `apps/dashboard/src/views/monitoring.tsx` + presentation/copy layer —
  Chinese-first read-only `/monitoring` page (overview / re-analysis jobs /
  notification deliveries / audit details). Every important operational state
  has intentional zh/en copy with raw codes retained; empty, not-configured
  and error/conflict states are distinct; IDs and hashes stay inside
  technical details; there are zero mutation controls.
- `scripts/dashboard_cross_stack_smoke.py` — extended to build a genuine
  store chain with the real model/store builders, including an R2-orphan
  delivery fixture, and to drive it through the real API and the real
  Worker/Vite preview.

The D2B-R2 accounting distinction is part of the delivered contract:
`attempt_count` (persisted attempt outcomes) and `dispatch_claim_count`
(consumed authorized outbound transport slots) are separate fields, separate
labels and separate explanations in API and UI; `unresolved_claim_numbers`,
`AMBIGUOUS`/`ORPHANED_DISPATCH` and pointer states
`CURRENT`/`MISSING`/`STALE_REPAIRABLE` survive the whole
Python -> OpenAPI -> Worker -> client path. Nothing anywhere flattens them
into a generic retry/health count.
