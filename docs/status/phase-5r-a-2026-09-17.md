## 4. 为什么 M2-T 必须先做

M2-T 之前的 FQGate 实现仍有 local-only 语义：

- persisted adapter id 为 `fqgate-local-market-history`；
- transport failure 被写为 `FQGATE_LOCAL_GATEWAY_UNREACHABLE`；
- `credential_ref` 被禁止；
- HTTP 401/403 被归为 FQGate entitlement denial。

这些规则不能直接搬到 Tunnel 模式。远程 401/403 可能来自 Cloudflare Access 或
bridge policy；DNS/TLS/Tunnel/bridge 故障也不是本机 FQGate 不可达。M2-T 必须先把
transport/auth/bridge/provider 四层诊断拆开，同时保留 M2-A 已完成的 provider
fail-closed 语义。

## 5. M2-T 实际实现与剩余 blocker

本轮实现内容：

- legacy `fqgate-local-market-history` v1 plans/receipts/batches 保持可读取和离线
  replay；旧 v1 endpoint 解析形状不被 retroactive 收窄；新增 `fqgate-market-history`
  v2 adapter/decoder 注册；
- 新请求显式写 `endpoint_kind` 与支持的 `fqgate-envelope-v1` contract；LOCAL_DIRECT
  只接受 loopback FQGate history endpoint，REMOTE_BRIDGE 只接受显式 HTTPS operation
  endpoint，不做 local/remote fallback 或 route discovery；
- 复用 `credential_ref`、resolver 与现有 header transport seam。credential 只在
  outbound request 出现，缺失时在 transport 前 fail closed；内置 HTTP transport
  默认拒绝 redirect，adapter 拒绝变更 URL 的响应；
- remote transport failure、remote auth/access 401/403 与 remote HTTP 5xx 分别保留
  `FQGATE_REMOTE_ENDPOINT_UNREACHABLE`、`FQGATE_REMOTE_AUTH_DENIED`、
  `FQGATE_REMOTE_HTTP_ERROR_UNCLASSIFIED`；remote 401/403 的 entitlement 保持
  `UNKNOWN`。无稳定 bridge error contract，未新增 bridge-specific mapping。

剩余跨仓库 blocker：`fqgate-remote-bridge` 当前 `main` 尚未实现 Phase 4 的
allowlisted read-only remote market-history route 和 machine-auth contract。因此：

- Turtle 已完成 deployment-neutral adapter、legacy compatibility、credential seam、
  remote fake-transport tests 和 layered diagnostics；
- 不得虚构 remote bridge path、Cloudflare auth header contract 或 live success；
- M2-T 以 `REMOTE_BRIDGE_LIVE_UNPROVEN` 关闭 Turtle 侧代码边界；
- 下一阶段 M2-B 仍可继续通过 LOCAL_DIRECT 运行，不需要等待 Tunnel 功能全部完成。

未来 remote bridge route 发布后，再补一个有界 A-share dual-path smoke proof；这只
证明 transport compatibility，不自动升级 H 或完整 historical capability。
