## 5. 下一执行目标：M2-B

M2-B 的唯一目标是判断 FQGate 能否获得一个**有界的 H-share `MARKET_BAR` source role**。
它首先是 live-evidence gate，而不是新增 provider 的编码任务。

必须使用 owner 实际观察到的 H identity；当前已有候选 `UHKM/HK0700`，但它仍只是
owner-observed candidate，不得扩展成通用 H market mapping。对该 exact identity 执行两个
不重叠窗口：

1. 一个近期窗口；
2. 一个至少早一年以上的历史窗口。

若两个窗口都成功，再执行一次 bounded acquire -> raw CAS -> compile -> `--verify-replay`。
只有这种成功证据才能选择 FQGate 作为 bounded H price source。

决策必须区分以下三类情况：

- **成功**：双窗口都返回受支持的 unadjusted daily bars，且 bounded acquire/replay 稳定；
  记录 FQGate 被选中，然后进入 M2-E selection record / 后续 historical work；
- **真实 provider/path 失败**：在可用的本机 FQGate 环境中完成实际 probe，但仍获得
  evidence-supported route/auth/provider/schema/no-row/coverage failure；记录精确 blocker，
  然后 M2-C（Futu OpenD）成为下一候选；
- **执行环境不可用**：Codex/runner 无法访问 owner 的本机 FQGate、没有有效登录会话，
  或根本无法执行 live probe。这不是 FQGate provider failure，不得因此跳到 M2-C 或
  声称 FQGate 不合格；M2-B 保持 blocked，输出可在 owner 环境直接执行的命令即可。

不得把旧的单窗口 timeout、fake transport、remote-bridge Phase 3、Tunnel 规划或 API docs
当成 M2-B 成功/失败证据。
