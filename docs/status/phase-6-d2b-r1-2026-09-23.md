## Delivered boundary

Phase 6-D2B-R1 hardens the existing D2B delivery boundary in place. D1,
D2A/R1, Phase 6-A/6-B/6-C, `strict-v1`, valuation, hard-gate, monitoring
cursor and re-analysis semantics are untouched.

- **Durable dispatch-start evidence (F1).** The new immutable, canonical,
  hash-validated `MonitoringDispatchClaimV1` contract (checked-in schema
  `schemas/monitoring-delivery-dispatch-claim.schema.json`) is persisted
  through the existing immutable create-only store path **before** the
  transport may write any request byte, but after in-memory endpoint/auth
  resolution (an unresolved endpoint can therefore never manufacture a
  claim). Claim content is fully deterministic — no wall-clock field — so
  re-saving the same claim for a resumed attempt is byte-identical and can
  never raise a spurious immutable-conflict. A claim without its terminal
  attempt artifact is an *orphaned dispatch*: `derive_delivery_state`
  derives terminal `AMBIGUOUS` with the new `ORPHANED_DISPATCH` error code
  and zero automatic resend for the default
  `receiver_idempotency_declared=false`; only the explicit
  `receiver_idempotency_declared=true` policy permits a bounded retry of the
  same deterministic delivery key (`attempt_number == attempts + 1`,
  monotonic), and never beyond `max_attempts`. Multiple unresolved claims, a
  non-monotonic unresolved number, or a claim bound to a different
  intent/payload hash fail closed.
- **Per-delivery OS single-flight exclusion (F2).** The new
  `monitoring_delivery/locking.py` takes a non-blocking exclusive `flock` on
  `delivery_root/locks/<delivery_id>.lock` as the first and only liveness
  authority, held across intent persistence, state validation/repair,
  dispatch-claim publication, the transport call, attempt persistence and
  latest-state publication. Only the platform's real contention errors
  (`BlockingIOError`/`EAGAIN`/`EWOULDBLOCK`/`EACCES`) map to
  `DeliveryLockBusyError`/CLI `DELIVERY_BUSY` (new additive exit 3, zero
  outbound requests); every other open/flock/filesystem error fails closed
  as `DeliveryLockError` (exit 2) and is never disguised as busy. The lock
  file carries no mutable holder record, and the receiver's
  `Idempotency-Key` is never relied on to resolve local concurrency.
- **One monotonic end-to-end HTTP deadline (F3).** `WebhookHttpTransport`
  now treats `timeout_seconds` as one overall monotonic deadline from an
  injectable clock. The connect/TLS phase receives the full remaining
  budget; the request-write/response-header wait and **every** bounded
  response-body read each re-derive and re-apply only the remaining budget
  through `sock.settimeout`. Deadline expiry proven to precede any request
  byte is honestly retryable (`DEADLINE_EXHAUSTED_PRE_DISPATCH`, new code);
  expiry after dispatch may have started — including between repeated body
  reads — is `AMBIGUOUS`/`TIMEOUT_AFTER_DISPATCH`. A `TimeoutError` or
  connection loss during body reads is now also classified
  post-dispatch `AMBIGUOUS` instead of escaping as an unclassified error.
- **Truthful read-only pointer status (F4).**
  `delivery_status_projection`/`tve watch delivery-status` now *validate*
  the published latest-state pointer instead of reporting path existence:
  `pointer_status` is `MISSING` (nothing published, not repaired by
  status), `CURRENT` (canonical and byte-identical to the immutable-artifact
  derivation) or `STALE_REPAIRABLE` (valid but behind the immutable
  artifacts; only the mutating delivery path may repair it, and the
  repair-behind rule is shared with the service through
  `published_state_is_behind`). Corrupt, non-canonical, foreign-slot and
  contradictory pointers fail closed with `DELIVERY_POINTER_CONFLICT`
  (CLI exit 2). The projection also reports dispatch-claim evidence
  (`dispatch_claim_count`, `unresolved_dispatch_claim`) for each delivery.

No endpoint, token or other secret value enters any dispatch claim,
attempt, state, status projection, lock slot, CLI output or exception text;
the existing secret-canary matrix continues to scan every ledger file
including the new claim and lock paths.
