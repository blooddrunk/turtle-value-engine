## What changed

All changes are in `scripts/monitoring_production_ops.py` plus sixteen new
deterministic regressions in `tests/test_monitoring_production_ops.py`.

1. **One canonical parser/validator (finding F1).** `environment_file_values()`
   is now the single source of truth for every production-operations
   credential path — render gating, preflight, effective secret
   scanning/redaction (verify and `_service_wake` journal redaction, D3
   payload scan, live-proof/recover-proof/report artifact scans and
   serialized-report guards via `effective_secret_values()` /
   `_effective_secret_scan_map()`), and delivery completeness
   (`_delivery_section`). It accepts only a deliberately unambiguous subset
   of systemd `EnvironmentFile=` semantics:
   - UTF-8 text (strict decode; bounded to 64 KiB); blank lines and
     whole-line `#`/`;` comments are ignored;
   - every assignment is exactly one physical `NAME=VALUE` line starting at
     column 0; `NAME` must be one of the referenced secret names, each
     present exactly once; duplicates, unknown/unrelated keys and
     `export NAME=...` forms are rejected (no unrelated process-environment
     injection);
   - `VALUE` is non-empty and carries no leading/trailing/embedded
     whitespace, no control character, no quote and no backslash (covering
     unquoted escapes and backslash-newline continuation), and is used
     byte-for-byte after UTF-8 decoding and line-ending removal;
   - `=`, `#`, `;`, `?`, `&`, `%` and other URL punctuation inside the value
     are literal data, never inline comments.
   Any syntax-level violation returns `({}, reason)` — no value whose
   interpretation is not provably identical under systemd is ever released.
   A file whose present lines are all canonical but which is missing a
   referenced name returns its partial values **with** a non-`None` error:
   those bytes are still exactly what systemd would inject for them, so the
   fail-safe scan/redaction set keeps the R1 coverage (dual-source behavior
   unchanged, R1 tests unmodified), while every gating path fails closed on
   the error. Rejection reasons name only line numbers, violation
   categories and referenced (public) names — never file content.
2. **Truthful render gating (finding F2).** `cmd_render()` now proves, before
   the output directory is created and before any unit/runner-config/
   render-plan artifact byte is written: the R1 metadata boundary
   (absolute/in-private-root, resolved-path containment, regular file,
   owner-only permissions), actual readability, canonical syntax, and
   referenced-name completeness — all through the same canonical parser.
   Any failure stops at `MANUAL_SECRET_REFERENCE_REQUIRED` with the full
   six-item disclosure, the exact `_resume_command(..., "render")` and no
   secret value in the marker. Preflight's `delivery.secret-reference` check
   and `_delivery_section`'s live-proof delivery boundary report the same
   canonical reasons.
3. **Path injection hardening.** A configured `delivery_environment_file`
   containing control characters/newlines is rejected both at
   `ProductionConfigV1` parse time and by
   `validate_delivery_environment_file()` (the path is serialized verbatim
   into the unit's `EnvironmentFile=` line). R1's
   absolute/in-private-root, resolved-containment, regular-file and
   owner-only permission checks are unchanged, and the harness still never
   chmods or rewrites the owner's credential file.

## Deterministic regressions

Sixteen new tests in `tests/test_monitoring_production_ops.py` (67 total in
the file; 51 pre-existing, one adapted from permissive-quote parsing to the
canonical expectation, R1 tests otherwise byte-identical):

1. `test_r2_backslash_escape_is_rejected` — an unquoted systemd escape never
   becomes a service-effective value.
2. `test_r2_backslash_newline_continuation_is_rejected` — continuation is
   rejected without echoing the value.
3. `test_r2_quoted_and_multiline_values_are_rejected` — single/double quotes
   and multiline values are rejected, not approximately parsed.
4. `test_r2_render_missing_required_reference_stops_at_marker_and_writes_nothing`
   — render stops at the marker with a parser-valid resume command and
   leaves no unit/config/render-plan artifact.
5. `test_r2_duplicate_reference_is_rejected`.
6. `test_r2_unknown_environment_key_is_rejected_without_echoing_it` — the
   reason is line/category based and never echoes the key or value.
7. `test_r2_unreadable_credential_file_fails_closed_in_render_and_preflight`
   — a metadata-valid but unreadable file (deterministic `PermissionError`
   injection, independent of euid) stops render and preflight precisely.
8. `test_r2_canonical_url_punctuation_is_preserved_and_scanned_byte_for_byte`
   — `= # ; ? & %` survive byte-for-byte and are seen by
   `environment_file_values`, `effective_secret_values`, the scan map,
   `scan_bytes_for_secrets`, `redact_text` and a successful render whose
   artifacts stay value-free.
9. `test_r2_dual_source_mismatch_keeps_both_values_with_canonical_file` —
   the R1 dual-source scan/redaction behavior stays intact.
10. `test_r2_delivery_disabled_render_stays_compatible` — monitoring-only
    production behavior is unchanged.
11. `test_r2_no_render_artifact_on_rejected_credential_syntax` — a syntax
    violation leaves no newly rendered delivery-enabled unit behind.
12. `test_r2_export_whitespace_and_empty_value_forms_are_rejected` —
    `export`, whitespace-around-`=`/in-value and empty values are rejected
    with leak-free reasons.
13. `test_r2_environment_file_path_control_characters_rejected` — parse-time
    and validator-level rejection of newline/control-character paths.
14. `test_r2_preflight_reports_canonical_violation_precisely` — preflight
    surfaces the exact canonical violation as
    `MANUAL_SECRET_REFERENCE_REQUIRED` without the value.
15. `test_r2_delivery_section_rejects_non_canonical_file` — the live-proof
    delivery boundary fails closed on non-canonical content.
16. `test_r2_canonical_boundary_resume_command_is_parser_valid` — the
    render marker's resume command round-trips through `_build_parser()`.
