- Therefore a file-bound owner policy exception, decision record, or signed-lifecycle statement changed **after preparation but before execution** may still be consumed from stale memory even when trust root and evidence bundle are unchanged. This is a source-level hypothesis about disk/CLI contract freshness, **not a proven authorization bypass**. The files are meant to be immutable/create-only under normal producer workflows; tests must explicitly distinguish an external same-user mutation from supported normal operation.
- Required first proof: use the real `tests/test_activation_execution.py::_Env` disposable Ed25519 fixture and a deterministic CLI preparation→executor barrier. Replace one *named input file* with different valid/canonical bytes on disk (start with the hash-bound policy exception, then decision record if needed) while keeping trust-root and evidence unchanged. Independently show that a separately started fresh CLI invocation would BLOCK; then assert pre-fix actual exit/status, unchanged-or-changed config SHA, and that the mutated file truly differs. Only if the same-invocation run accepts stale input or otherwise contradicts the documented boundary should a surgical R3 fix be selected.

### F2: a hard-linked foreign regular lock inode — priority 2

- `activation_execution.py:_ConfigLock.__enter__` (`751–789`) now uses `O_NOFOLLOW` then `fstat` regular-file type proof before `flock`. This prevents final-component **symlinks** and FIFOs, but a **hard link** to an outside regular file is itself a regular directory entry, is not a symlink, and can reference the same inode.
