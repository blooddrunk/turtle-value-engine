### F1 — stale authority inside one apply invocation (4 red)

Deterministic barriers (library monkeypatch at the exact CLI-preparation →
executor and derivation → replace transitions) applied real trust-root
snapshot transitions to the real on-disk temporary trust root, with the real
CLI driven end-to-end (`record-decision` → READY preview → apply):

| barrier (within ONE apply invocation) | observed pristine-main behavior |
| --- | --- |
| signing key revoked after `_prepare_activation_inputs`, before `apply_profile_activation` | CLI **exit 0 `ACTIVATED`** — the config was replaced through the stale pre-lock registry/verifier objects; the on-disk latest snapshot had really changed (verified) but the re-derived in-lock plan never re-read it |
| key rotated (revoke old + enroll successor) at the same boundary | CLI exit 0 `ACTIVATED` through the stale authority |
| key revoked after in-lock derivation, immediately before the config `os.replace` (journal/before-image already durable) | CLI exit 0 `ACTIVATED` — no last-moment freshness anchor existed |
| evidence bundle statement tampered after preparation | CLI exit 0 `ACTIVATED` — the in-memory prepared evidence was used unchanged |

The already-covered "revoke between two separate CLI invocations" case
(preview → revoke → fresh apply) stayed blocked exactly as before
(`ACTIVATION_BLOCKED` + `OWNER_AUTHORITY_REVERIFICATION_*`), proving the
new tests target precisely the within-one-invocation race.

### F2 — final lock-component foreign inode (5 red)

`activation_root/locks/` is a legitimate real directory; the hostile entry
is only the final component `locks/<sha256-of-config>[:24].lock`:

| hostile final lock entry | observed pristine-main behavior |
| --- | --- |
| symlink → unrelated writable trap file (apply) | CLI **exit 0 `ACTIVATED`** — `os.open(O_RDWR\|O_CREAT)` followed the symlink and `flock` bound the executor's mutual exclusion to the **foreign inode outside the store**; the trap's bytes were not modified (the lock is never written), proving an open+flock of an external file |
| same symlink, trap flock held by the test process | CLI **exit 3 `ACTIVATION_BUSY`** — the foreign-inode flock genuinely contended, so a hostile lock layout could fabricate genuine-busy semantics (exit 3 must mean only real contention on the in-store lock) |
| same symlink (rollback) | CLI exit 0 `ROLLED_BACK` through the foreign inode |
| same symlink, trap held (rollback) | CLI exit 3 `ACTIVATION_BUSY` |
| FIFO at the lock path (apply) | CLI exit 0 `ACTIVATED` — the FIFO was opened and flocked as the lock |

Controls that stayed green on pristine main: a pre-existing **regular** lock
file works (`ACTIVATED`, same inode reused), a directory at the lock path
fails `ACTIVATION_LOCK_UNAVAILABLE` exit 2, real held-lock contention gives
exit 3 with zero work.

## 3. Minimal fixes (both reproduced; no UNPROVEN candidates)

`src/turtle_value_engine/evolution/activation_execution.py`:

- **F2**: `_ConfigLock.__enter__` now opens the lock entry with
  `O_NOFOLLOW` (POSIX; honest platform boundary — without it the post-open
  `fstat` regular-file check is the fallback) and proves the opened
  descriptor is a regular file. A pre-existing final-component symlink is
  refused by name (`ACTIVATION_LOCK_SYMLINK`), any non-regular entry by
  `ACTIVATION_LOCK_NOT_REGULAR`, before any inode is locked; the hostile
  entry and its foreign target are never unlinked or altered (no
  "delete stale lock" recovery exists). `ACTIVATION_LOCK_UNAVAILABLE` keeps
  classifying genuine open failures and `ACTIVATION_BUSY` keeps meaning only
  real flock contention on the in-store lock. Intermediate directory
  components remain covered by the R1 `_guard_contained_dir` checks.
- **F1**: new `_enforce_authority_recheck` runs an injected
  `authority_recheck` callable at two anchor points inside the per-config
  lock — (1) after the full in-lock re-derivation and every existing
  expected-identity check, immediately before the first durable write of
  the attempt, and (2) inside `_stage_and_replace` after the staged bytes
  are durable and the CAS hash re-read passes, immediately before the
  protected `os.replace` (the staged temp is removed on this refusal).
  Any named staleness blocker fails the apply closed with the new named
  status `ACTIVATION_AUTHORITY_STALE` (exit 1) and the config is never
  replaced. `apply_profile_activation` documents the additive parameter;
  library callers passing explicit in-memory verifier/trust-root objects
  keep the existing contract (`None` default performs no recheck). The
  early-return no-mutation paths (`COMPLETED_ALREADY`,
  `FINALIZED_AFTER_INTERRUPTED_REPLACE`) are deliberately not gated: they
  publish audit artifacts of an already-completed activation and consume no
  new authority. Rollback is unchanged (it acquires no new signed owner
  decision), except that it benefits from the same hardened lock entry.

`src/turtle_value_engine/cli.py`:

- `_prepare_activation_inputs` additionally records the prepared
  trust-root snapshot content hash and evidence bundle content hash;
  `_build_activation_authority_recheck` builds the CLI-only recheck closure
  that reloads the current latest snapshot and the strictly loaded evidence
  bundle inside the lock and reports named blockers:
  `AUTHORITY_TRUST_ROOT_SUPERSEDED` (any supersession — revocation,
  rotation or enrollment: deliberately conservative), 
  `AUTHORITY_TRUST_ROOT_UNREADABLE`, `AUTHORITY_EVIDENCE_CHANGED`,
  `AUTHORITY_EVIDENCE_UNREADABLE`. Only the apply path injects it; the
  preview stays byte-for-byte read-only and the planner command is
  unchanged.

Honest TOCTOU boundary (no invented atomicity): the recheck observes the
on-disk authority at the two anchor points; a change landing in the
remaining window between the second anchor and the `os.replace` (or after
it) is outside what this single-host executor can prevent without
cross-file global atomicity, which is explicitly not claimed. The refused
attempt's already-durable intent journal / before-image remain as immutable
audit history (stated in the refusal payload detail).

No persisted contract field or schema changed; `FAULT_POINTS`, receipts,
rollback intents/outcomes, fsync ordering, guards and every C4-A/R1 status
are unchanged.

## 7. Not verified / explicit residual boundaries

- No physical power-loss or multi-host concurrency certification (as in
  R1): interruption evidence is deterministic fault/monkeypatch injection
  plus fsync-call ordering proofs inherited unchanged from R1.
- The F1 recheck observes the authority at the two anchor points only; the
  residual window between the last anchor and the same-directory
  `os.replace` is honestly unguarded (no cross-file global atomicity is
  claimed or implementable here).
- `O_NOFOLLOW` final-component refusal is a Linux/POSIX guarantee (all CI
  hosts); on a hypothetical platform without it, the post-open `fstat`
  regular-file check still refuses FIFOs/devices/directories but cannot
  distinguish a symlink whose *target* is a regular file.
- A trust-root snapshot change of any kind (including a benign enrollment)
  conservatively blocks the in-flight apply with
  `ACTIVATION_TRUST_ROOT_SUPERSEDED`; the operator reruns preview + apply.
  This is the intended fail-closed semantics, not a false positive class.
