## 1. Reviewed defects

1. **`ALREADY_TARGET` inventory crash (non-default references).**
   `_classify_references` classified a watchlist (or normalized input /
   backtest manifest / surface snapshot) already pinned to the target profile
   as `ALREADY_TARGET` with an empty blocker, but the `ConfigReferenceV1`
   model validator required `DEFAULT_ALREADY_TARGET` for **every** kind. A
   target-pinned watchlist therefore aborted plan derivation with a pydantic
   `ValidationError` instead of producing a coherent read-only plan. Only the
   mutable project default is a no-op blocker; other artifacts already using
   the target are compatible.
2. **`allowlist_matched=None` passed plan-time authority reverification.**
   `_reverify_decision_authority` blocked only an explicit
   `allowlist_matched is False`; `None` — which the contract defines as "no
   allowlist was configured at all / no confirmation performed" — flowed
   through as if a positive match had been proven. A verifier that never
   confirmed the identity authorization could therefore co-authorize a READY
   plan.

## 6. Create-only cleanup inode/unlink race review (documented, not changed)

R2 additionally audited the C2-R1 failure-cleanup pattern used by
`_write_create_or_identical` (`src/turtle_value_engine/cli.py:1647`) and
`record_owner_decision_file`
(`src/turtle_value_engine/evolution/owner_decision.py:1310`): on a
write/fsync failure the call unlinks the path only after proving
`os.stat(path).st_ino == created_ino`.

- **Within the repository's writer model there is no executable
  reproduction.** A competing TVE writer that loses the exclusive
  `O_CREAT|O_EXCL` open never unlinks or replaces the path — it reads,
  compares, and either returns `IDEMPOTENT` or raises the classified
  immutability error. No interleaving of two repository invocations can
  place a different inode at the path between this call's inode check and
  its unlink, so the cleanup can only ever remove the partial file the
  failing call itself created. The existing R1 hook-orchestrated
  concurrency regressions (which reproduce the pre-R1 overwrite on the
  baseline and prove the fix) remain green.
- **Residual theoretical window:** a foreign (non-TVE) process with write
  permission on the output directory could replace the path between the
  `os.stat` inode check and the `unlink`, making the cleanup delete that
  replacement. Such an actor already holds a strictly stronger capability
  (direct unlink of arbitrary files in the directory), the window exists
  only on the failure path, and POSIX offers no portable
  unlink-if-same-inode primitive to close it (unlink-by-fd does not exist;
  Linux `renameat2` semantics do not provide remove-if-inode either).
  Following the review instruction, no fix is claimed and no
  arbitrary-multi-process-race verification is asserted; the exposure is
  recorded as a limitation of the cleanup best-effort, not of publication
  atomicity (which is kernel-enforced by the exclusive open).
