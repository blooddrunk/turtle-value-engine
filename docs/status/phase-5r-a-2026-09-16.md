### M2-A FQGate 诊断加固

M2-A 已完成离线实现和 fake-transport 回归覆盖。适配器现在能够区分本机连接失败、
返回的 HTTP 错误、结构化但语义未知的 provider code、无行、部分覆盖和不支持的
响应 schema，并把这些结果写入既有 `SourceProbeReportV1` 字段；没有新增 schema，
也没有改动 `acquisition.py` 的通用 retry 逻辑。

本次实现的关键约束：

- 401/403 只按 HTTP 事实记为 `FQGATE_ENTITLEMENT_DENIED`；本机 transport 连接异常
  记为 `FQGATE_LOCAL_GATEWAY_UNREACHABLE`。
- 当前 H 观察到的 HTTP 504 记为 `FQGATE_HTTP_504_UNCLASSIFIED`。即使响应带有
  `upstream_timeout` 一类字符串，也只保留受限的
  `FQGATE_PROVIDER_ERROR_CODE` 和 `FQGATE_PROVIDER_ERROR_UNCLASSIFIED`，不会升级为
  `FQGATE_UPSTREAM_TIMEOUT_CONFIRMED`。公开 FQGate client 只转发 provider code，
  没有提供可独立验证的 timeout/route code 语义，因此没有发明正向映射。
- H request 缺少实际 `market`/`code` 或使用模板值时，在网络前记为
  `FQGATE_H_ROUTE_UNVERIFIED`；不会从 listing、`hk` market group 或其他上下文推导
  FQGate ID。
- 200 + 合法行但日期范围不完整记为 `HISTORICAL_COVERAGE_INSUFFICIENT`；200 +
  零行记为 `HISTORICAL_NO_ROWS`；schema 漂移记为 `SOURCE_SCHEMA_UNSUPPORTED`。

当前支持状态仍为 `H_SOURCE_UNQUALIFIED`。此前 owner-observed 的
`UHKM/HK0700`（`HK00700`）历史请求仍是 HTTP 504、没有数据，M2-A 只使该事实的
诊断更精确，并没有把它解释为 H 路由拒绝、上游 timeout、权限拒绝或 H 不支持。
因此没有选择 FQGate 作为 H 价格来源，也没有启动 Futu/AKShare provider 扩展。
