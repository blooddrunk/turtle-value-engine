## 3. Implementation (commit `c38af8c1228d03de2a110d2bf8b9d2e74797ccbc`)

`evolution/owner_trust_store.py` (+141/−13), no persisted V1 contract
field or schema changed:

- `_check_bundle_directory_shape`: one component-manifest shape contract
  shared by the strict loader and the audit replay — a VALID bundle
  directory is exactly the six files, an INVALID no-record capture exactly
  the five; missing, extra, symlinked and non-file entries are classified
  fail-closed store errors (read-only; immutable evidence is never
  deleted or rewritten).
- `_record_signed_payload_divergences`: the owner-signed decision-input
  fields (`_DECISION_CONTENT_FIELDS`, the same binding the plan-time
  re-attestation uses) plus `provenance.source_revision` must be embedded
  verbatim in the persisted record.
- `reverify_owner_decision_evidence`: reads and compares the physical
  `verification.json` (`VERIFICATION_FILE_DIVERGED`) and `record.json`
  (`RECORD_FILE_DIVERGED`), reconciles the manifest registry identity
  with the registry inside the persisted snapshot
  (`REGISTRY_IDENTITY_DIVERGED`), and appends
  `RECORD_SIGNED_CONTENT_DIVERGED` / `RECORD_SOURCE_REVISION_DIVERGED` /
  `SIGNED_INPUT_UNUSABLE` for the forged-record classes. Unreadable or
  shape-violating components still fail closed as classified errors.
- `load_owner_decision_evidence` (strict consumer path behind
  `plan-activation --authority-evidence`): gains the same shape check,
  registry-identity fail-close and record-vs-signed-bytes fail-close.
- Semantics kept distinct: historical replay integrity (offline audit) is
  never fresh owner authority — plan-time re-attestation still verifies
  the signature against the operator-owned CURRENT trust root, and an
  honestly captured REJECTED bundle still replays
  `REPLAYS_BYTE_IDENTICAL` as integrity-only evidence.

`docs/operations/owner-provenance-walkthrough.md` §0–§3/§5 repaired:
outside-repository absolute directories created with `mkdir -p` and
inspected (`ls -ld`, `realpath`) before use; one encrypted PKCS#8 Ed25519
private key persisted at `~/tve-trust/private/owner.pem` with an
interactively prompted passphrase (`getpass`, never argv/Git/CI/chat);
the same persisted key reloaded and signing in a fresh process; CLI exit
codes 0 (integrity-only replay, including REJECTED evidence) / 1 (named
`*_DIVERGED` mismatch) / 2 (classified fail-close) documented; failure

## 5. Limitations and boundaries

- The offline replay proves **integrity of persisted evidence**, not
  owner authority, and does not re-execute profile/economic audits (the
  C1 audit inputs are not part of the evidence bundle); fresh authority
  remains exclusively the plan-time re-attestation against the operator's
  current trust root.
- Shape enforcement covers the bundle directory itself; it cannot protect
  against a whole-directory replacement by an actor with write
  permission on the evidence root (consistent with the C2-R2 recorded
  limitation class) — content hashes and deterministic ids make any such
  replacement detectable by comparison with an independently retained
  bundle id.
- The walkthrough smoke uses throwaway keys and a throwaway passphrase;
  real owner key provisioning, strict-v2 economic acceptance and any
  activation remain explicit manual owner decisions outside R1.
