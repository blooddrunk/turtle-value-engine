## 2. Reproduced defects on pristine main (tests-first)

The **final committed probe file** was executed in an isolated worktree
pinned at the unmodified implementation baseline `4e00975` (`.venv`
symlinked; no repository code changed there), producing exactly the same
failure set as the initial pre-implementation run of the tests-first
commit `861f3e4`:

```text
$ python -m pytest tests/test_owner_readiness_summary_r2_probes.py -q
11 failed, 2 passed
```

The two passing cases are deliberate unchanged-invariant controls
(repeatable-input order/multiplicity inside the tail; absence of
private-key material). The eleven failures are the two defects:

- **F1 (P2, shell-reproduced)** — extracting the command tail
  **literally** (`step.rsplit("：", 1)[1]`, no `rstrip`/no `。` removal of
  any kind) and pasting it into a no-op `tve` stub delivered the sentence
  full stop as part of the last shell argument:
  `… '--activation-root' '/tmp/…/activation。'` instead of
  `'/tmp/…/activation'` (`test_f1_authenticated_retry_tail_is_paste_
  ready_verbatim` and every other F1 probe). The same corrupted last
  argument appeared for the status, preview and journey-start retry
  commands, across hostile metacharacter paths (spaces, single **and**
  double quotes, `$`, backticks, `;`, `<`/`>` and Chinese text — where a
  **genuine** filename ending in `。` was correctly preserved *inside* the
  quoted path, proving the sentence punctuation — not the character
  class — is the defect), and across **all eleven** journey states
  (`test_f1_all_journeys_tails_are_complete_safe_and_literally_copyable`).
  The canonical-line round-trip probe (`shlex.join(shlex.split(tail)) ==
  tail`) failed for every command-bearing step, and the real-CLI replay
  of the literal retry tail could not reproduce the observation
  (`test_literal_retry_tail_replays_the_exact_observation` /
  `test_summary_and_literal_tails_are_zero_write_and_socket_free`).
- **F2 (P3)** — the journey-start dossier step contained the exact
  exclusivity claim `是旅程中唯一写文件步骤` while
  `plan-activation --output` also writes a file
  (`test_f2_no_write_command_step_claims_to_be_the_sole_write_step`);
  the plan-activation write was not framed as an *additional* write
  (`test_f2_both_write_commands_disclose_their_write_and_output_choice`).

## 3. The minimal repair

1. **Copy boundary (F1):** every executable command is now the complete
   final segment after the last full-width colon **with nothing after
   it** — the nine command-bearing steps end at the quoted command, and
   human-readable punctuation stays before the colon. `shlex.join`
   composition, argument vectors, replay fidelity and the
   complete-read-only-operation guarantee are untouched, so paths with
   spaces/quotes/metacharacters and genuine `。`-ending filenames still
   round-trip byte-for-byte. Copying the displayed tail now requires
   deleting nothing.
2. **Write-step accuracy (F2):** the dossier step discloses that
   `decision-dossier --output` writes the operator-chosen Markdown file
   and no longer claims exclusivity; the plan-activation step now says
   the command **同样** (also) writes the operator-chosen plan file. Both
   remain prose-only (never paste-ready), both name the operator's own
   `--output` path choice, and neither is labelled read-only.
3. **R1 extractor hardening:** the R1 probe helper's silent
   `。`-stripping — the masking behavior this review identified — was
   removed so the R1 suite now also proves literal copy fidelity; its
   docstring states the hardened contract. No R1 safety assertion was
   weakened.

The persisted summary contract is unchanged: no model field, schema
file, journey state, exit class, identity algorithm or literal changed.
`next_steps_zh` content differs only in the fixed hint strings (the
`content_sha256` self-check recomputes over the new content exactly as
before).
