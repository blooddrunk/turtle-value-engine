## What changed

`RunnerLease.probe()` — the read-only observation path behind
`GET /v1/monitoring/operations`, `tve watch unattended-status` and the
projection — no longer acquires any OS lock. The defect was that the probe
took the same `flock(LOCK_EX | LOCK_NB)` as the authoritative
`RunnerLease.held()`, so a D3/API/Dashboard read could make an otherwise
uncontended unattended runner invocation return
`RunnerLeaseBusyError / LEASE_BUSY` with zero D1 work.

The corrected protocol is passive and structural (no sleeps, retries,
timeouts or probability reduction):

- the probe opens the slot `O_RDONLY` and never flocks it;
- liveness is proven from the kernel's `/proc/locks` table: a granted
  `FLOCK` entry bound to the lease file's `device:inode` proves a live
  exclusive holder without taking one (`_scan_flock_holder`, bounded read,
  blocked-request `->` lines skipped, non-`FLOCK` lock domains ignored,
  unparseable/truncated/missing tables classified as capability-unavailable);
- each observation reads the slot bytes twice around two lock-table scans;
  bytes only ever change under the authoritative exclusive lock, so a
  difference proves a writer was active inside the window and triggers a
  bounded byte-evidence-driven re-observation (exhaustion degrades to the
  conservative `UNKNOWN`, never a guess);
- `ABANDONED`/`corrupt` remain proven statements: a trustworthy lock-free
  table plus stable bytes (the exact conditions the old lock-acquiring probe
  guaranteed by owning the lock);
- where passive proof is impossible (non-Linux platform, unavailable or
  untrustworthy lock table, persistently changing bytes) the probe returns
  the explicit additive conservative `UNKNOWN` state instead of fabricating
  `LIVE`/`FREE`/`ABANDONED`.

`RunnerLease.held()` and every D2A-R1 semantic are unchanged: the
non-blocking exclusive flock remains the first and only liveness authority
for work, only real contention maps to `RunnerLeaseBusyError`, unrelated
open/flock failures still fail closed, and slot identity/record semantics
are untouched.

Additive public contract change: `LeaseState.UNKNOWN` and projection
`lease_state` value `UNKNOWN`. The monitoring projection JSON Schema, the
Surface OpenAPI export and the generated Dashboard API types were
regenerated and are drift-checked; the Dashboard renders `UNKNOWN` through
the existing intentional caution presentation (raw code retained, no
corruption claim, never displayed as live or free).

## Deterministic concurrency proof (all fail on the pre-R1 implementation)

Adversarial verification: the new tests were executed against a hybrid of
the baseline `lease.py` (old flock-acquiring probe retained) with the new
symbols appended — all four selected tests failed
(`AssertionError: the lease observation path must not take OS locks` and
concurrent observer/runner failures), then passed 1.42 s after restoring the
fixed implementation.

- **Case 1 — no real holder** (`test_d3_observation_paused_mid_probe_cannot_busy_real_runner`,
  two-process file barriers): a real observer subprocess is held inside its
  critical observation section (kernel lock-table scan) while the real
  `MonitoringRunnerService.run()` runs concurrently. The observer process
  forbids every `fcntl.flock` call. Results: zero observer lock attempts, no
  `RunnerLeaseBusyError`, D1 entered exactly once, terminal
  `COMPLETED_NEW` reached, and the observer finishes cleanly converging on
  the post-run record (`ABANDONED` with the completed activation id).
- **Case 2 — real holder** (`test_real_holder_remains_authoritative_while_d3_observes`):
  process A owns the real `RunnerLease.held()`; the D3 projection is built
  with all flock calls forbidden in-process (succeeds, kernel-proven
  `LIVE`, no conflicting authority); the competing real runner still raises
  `RunnerLeaseBusyError` with zero D1/provider calls; after A releases, the
  slot is usable again and a real run completes.
- **Case 3 — bounded repeated matrix**
  (`test_bounded_observer_runner_matrix_has_zero_observer_induced_busy`):
  ten tightly coordinated iterations (thread/event barriers, no arbitrary
  sleeps), each holding the observer inside its critical section while a
  fresh real activation runs to terminal. Exactly zero observer-induced
  `LEASE_BUSY`; `d1.calls == 10`; zero flock calls from the observer thread;
  every observer converged on the completed activation's record.
- Supporting truthfulness units: the probe takes no OS lock for any slot
  state; a real kernel holder classifies `LIVE` passively with zero probe
  lock attempts; `UNKNOWN` under an unavailable capability (canonical and
  torn bytes); `ABANDONED`/`corrupt` only from a proven lock-free slot with
  stable bytes; bounded re-observation on byte changes; the lock-table
  parser itself (granted vs blocked lines, foreign inodes, POSIX/OFDLCK
  domains, malformed/truncated/missing tables) against fixture tables and
  the real kernel table with a live lock on a private file.

Preserved D3 invariants were re-proven by the existing suite unchanged:
projection reads write/repair nothing (file/byte inventories identical),
secrets/local roots/holder tokens never reach API/browser output,
corrupt/foreign evidence fails closed or is explicitly conservative
(`UNKNOWN`), `attempt_count` vs `dispatch_claim_count`, `unresolved_claim_numbers`,
`AMBIGUOUS`/`ORPHANED_DISPATCH`, `CURRENT`/`MISSING`/`STALE_REPAIRABLE` stay
exact, the API remains fixed read-only `GET /v1/monitoring/operations` (405
mutations, 404 subpaths), the Worker exposes only
`/api/v1/monitoring/operations`, and the Dashboard keeps zero
run/retry/resend/repair/acknowledge/trading controls.
