## Delivered boundary

The additive `src/turtle_value_engine/monitoring_runner/` package provides:

- `RunnerConfigV1` — one explicit typed non-secret JSON input
  (`config/monitoring-runner.example.json`) carrying runner identity, explicit
  store/workspace roots, the frozen or wake-resolved `as_of` policy, an
  explicit fixed or `window_days`-relative acquisition window, and the same
  deny-by-default live/cache-replay acquisition opt-ins as D1;
- `RunnerActivationIntentV1` — persisted immutably BEFORE entering D1; freezes
  the exact resolved `MonitoringCycleSpecV1` (including the PIT `as_of`) plus
  a SHA-256 request fingerprint over every explicit input needed to reproduce
  the same D1 invocation;
- an exclusive single-host lease (`RunnerLease`/`RunnerLeaseV1`) proven by an
  OS-level `flock` held for the whole invocation: a live holder can never be
  stolen from; an abandoned holder (process gone) is recovered explicitly; the
  losing invocation of an overlap exits with classification `LEASE_BUSY`
  (CLI exit code 3) having performed zero provider/model/D1 work;
- `RunnerReceiptV1` + `RunnerLatestPointerV1` — a terminal receipt binding the
  activation to the exact `MonitoringCycleResultV1` content hash and
  `MonitoringAlertBatchV1` identity/hash with the D1 status/failure code
  recorded verbatim, published with an atomic repairable latest pointer;
- `MonitoringRunnerService` — one scheduler-neutral wake: settle crashed prior
  state, resume the unfinished activation (identical `activation_id`, identical
  frozen `as_of`; a later wall clock never derives a new cycle identity),
  repair the runner layer from existing D1 terminal artifacts through the
  existing `MonitoringCycleStore.load_terminal` public boundary without
  repeating provider/model/re-analysis work, or create exactly one new
  activation; then enter the unchanged Phase 6-D1 boundary;
- `tve watch unattended-run --runner-config <path>` (exit 0 completed /
  3 lease busy / 2 fail-closed) and
  `tve watch unattended-status --runner-root <path> [--runner-id] [--activation-id]`
  with bounded, secret-free, holder-token-free JSON output;
- checked-in reference systemd service/timer templates
  (`deploy/monitoring/turtle-value-monitor.service|timer`, explicit persistent
  paths, no embedded credentials, `Persistent=true`, `SuccessExitStatus=3`)
  plus `deploy/monitoring/README.md`; `systemd-analyze verify` runs as an
  ordinary CI step;
- checked-in schemas with drift tests for every persisted runner contract
  (activation, lease, receipt, latest/active pointers) and the config model.

Phase 6-B acquisition, Phase 6-A planning/commit/cursor semantics, Phase 6-C
execution and Phase 6-D1 cycle/alert semantics are consumed only through their
existing public boundaries. The unresolved-current-run D1 blocker passes

## Automatic verification

`tests/test_monitoring_runner.py` contains 25 deterministic tests covering the
entire D2A matrix:

- first activation -> exactly one D1 call -> terminal receipt/pointer;
- overlapping invocations -> exactly one lease owner, loser zero work;
- abandoned lease recovery; live lease never stolen;
- crash after intent before D1 terminal -> same activation and frozen PIT
  reused across an advancing clock;
- crash after D1 terminal before receipt -> repair with byte-identical
  Phase 6-A/6-C/D1 trees and unchanged provider/model call counts;
- crash between intent and active pointer -> unfinished intent adopted;
- crash before active-slot clear -> settled, then a genuinely new activation;
- repeated wake with identical request -> `COMPLETED_REUSED` with no new D1
  call;
- tampered intent/lease/latest-pointer/receipt, conflicting pointer and two
  unfinished activations -> fail closed;
- watchlist or config change under an unfinished activation -> fail closed;
- unresolved-current-run blocker recorded factually without pointer movement;
- no-event cycle -> zero re-analysis/model calls;
- config requires an explicit acquisition mode (mutual exclusivity);
- socket-blocked cache replay through the runner with zero source calls;
- bounded secret-free status output (holder token excluded);
- in-process CLI lease-busy exit code 3;
- a real subprocess black-box test (run/status/reuse/busy) over a seeded
  raw cache;
- `systemd-analyze verify` on the checked-in units;
- proof that no scheduled GitHub Actions monitoring workflow exists.
