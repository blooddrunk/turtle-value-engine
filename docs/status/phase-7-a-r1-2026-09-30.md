## 9. Post-closure audit correction and follow-up

A later same-day review
(`docs/status/phase-7-a-r1-post-closure-review-2026-09-30.md`) preserves the
R1 closure but identifies two blockers before Phase 7-B:

1. `CalibrationEvidenceBindingV1` is internally tamper-detecting but is not
   yet an authoritative unique freeze anchor for one `experiment_id`.
   `BacktestWorkspace` stores bindings by content-derived `binding_id`, the
   CLI accepts an arbitrary binding path, and a fresh self-consistent binding
   can be rebuilt over substituted same-id manifest content or non-scoring
   observation provenance. R1 detects substitution only when the original
   calibration-time binding is already trusted and supplied.
2. Sections 6-7 above overstate what the generated checked-in JSON Schema
   enforces. The Pydantic model validator enforces the exact nineteen-check
   sequence. The current schema enforces the nineteen-item count and the
   allowed name enum, but it does not encode per-position order/uniqueness;
   schema-only validation can therefore accept a reorder or a
   count-preserving duplicate/omission.

The corrective package
`docs/goals/phase-7-a-r2-authoritative-freeze-anchor-hardening.md` is selected
before any candidate-profile materialization, `strict-v2`, profile PR or
human-approval workflow. The historical exact-head CI evidence and all other
R1 closure claims remain unchanged.
