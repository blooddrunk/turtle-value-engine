### The load-to-hash interval (all barriers deterministic, no sleeps)

`cli._prepare_activation_inputs` parsed each named input file through its
loader (first read) and only afterwards called
`_prepared_input_file_sha256s`, which re-read the same paths (second
read) to record the R3 freshness digests. Three probes replaced one named
input with different valid canonical bytes strictly inside that interval,
driving the real CLI end-to-end (`registry init` → `record-decision` →
READY preview → `activate-profile --apply`) with the trust root and the
evidence bundle proven byte-identical throughout:

| barrier (within ONE apply invocation) | observed pristine-main behavior |
| --- | --- |
| policy-exception file replaced at `_load_policy_exceptions` return — immediately after the parser consumed the ORIGINAL bytes, strictly before the digest read | CLI **exit 0 `ACTIVATED`** — the plan was derived from the stale in-memory exception while the recorded digest was the NEW on-disk bytes' hash |
| same replacement at `_prepared_input_file_sha256s` entry — immediately before the digest read itself (the widest deterministic point of the interval) | CLI **exit 0 `ACTIVATED`** |
| decision-record file replaced (same `decision_record_id`, altered authority annotation → different `content_sha256`) at the same digest-entry barrier | CLI **exit 0 `ACTIVATED`** through the stale in-memory record |

A one-off baseline observation (disposable fixtures) recorded the exact
identity violation for the exception probe:

```text
recorded prepared_input_file_sha256s["policy-exception[0]"]
    = db2d3f32c039d7c96c4f92c3513ac608fa20fac803a72f38bb5aaf4a870c604d
    = sha256(mutated on-disk bytes)                <- the digest read
sha256(consumed original bytes)
    = 9fc6236ed9f6b7e0e43e8167dfe73d6980fabb3eb8af4fe7048225972bc355af
same invocation: exit 0, status ACTIVATED,
    prior_default_profile strict-v1 -> activated_default_profile strict-v2,
    receipt + journal published, config file really replaced
```

Because both R3 anchors re-hashed the unchanged NEW on-disk bytes against
the recorded NEW digest, neither anchor fired: the executor completed a
strict-v1→strict-v2 activation consuming prepared objects whose on-disk
replacements a separately started invocation refuses. The required truth
controls were proven first and stayed green on pristine main:

- `test_r4_fresh_invocation_on_mutated_exception_blocks` — a fresh CLI
  invocation on the mutated exception bytes BLOCKS (exit 1,
  `ACTIVATION_BLOCKED`, `DECISION_EXCEPTION_BINDING_STALE`, config
  unchanged, zero receipts), so the replacement changes authorization
  when loaded fresh;
- `test_r4_passthrough_digest_barrier_control_completes` — the identical
  monkeypatch barrier with NO mutation leaves the ordinary apply
  byte-identical (exit 0 `ACTIVATED`, same receipt, same activated
  bytes), so the barrier mechanism itself does not alter behavior.

## 3. Minimal repair (same consumed bytes; no third read)

`src/turtle_value_engine/evolution/owner_decision.py`:

- additive `load_decision_record_with_bytes` /
  `load_decision_revocation_with_bytes` return the parsed object together
  with the exact consumed buffer; the single `_regular_file_bytes` read
  stays inside the unchanged try/except, so every path-mode error message
  and class is preserved, and the existing `load_decision_record` /
  `load_decision_revocation` delegate to them (one read per call; the
  public signatures are unchanged and re-exported).

`src/turtle_value_engine/cli.py`:

- `_prepare_activation_inputs` now reads every actually supplied named
  input file exactly ONCE into a label-keyed consumed map —
  `decision-record[i]`, `revocation[i]`, `policy-exception[i]`,
  `boundary-input`, `signed-revocation[i]`, `signed-supersession[i]` —
  and parses each prepared object from that buffer;
  `prepared_input_file_sha256s` hashes those same buffers. No path is
  re-read for hashing, and no digest is ever derived from bytes the
  parser did not consume.
- `_load_policy_exceptions` gains an additive `bytes` mode that parses
  the exact pre-read buffer (`parse_constant` rejection unchanged); its
  path form and its other two callers (`record-decision`,
  `decision-dossier`) are unchanged.
- `_prepared_input_file_sha256s` derives the label-keyed digests from the
  consumed buffers (the R3 label scheme and `_prepared_input_path` anchor
  resolution are unchanged).

Both R3 in-lock anchors are unchanged and remain the on-disk recheck: the
reproduced interleaving now refuses at the FIRST anchor (exit 1,
`ACTIVATION_AUTHORITY_STALE`,
`AUTHORITY_INPUT_CHANGED:policy-exception[0]` /
`AUTHORITY_INPUT_CHANGED:decision-record[0]`) before any durable write —
no journal, before-image, receipt or staged temp exists after the
refusal — and a fresh invocation on the mutated bytes still blocks with
its own named blocker (asserted inside the probes). No persisted contract
field or schema changed; exit classes, lock behavior, receipts, rollback,
fsync ordering, the read-only preview/planner semantics and the library
explicit-verifier contracts are unchanged.

## 7. Not verified / explicit residual boundaries

- The two-anchor observation semantics are unchanged from R2/R3: no
  cross-file or cross-host global atomicity is claimed; the residual
  window between the last anchor and the same-directory `os.replace`
  remains honestly unguarded.
- The `revocation[i]`, `boundary-input`, `signed-revocation[i]` and
  `signed-supersession[i]` classes were not adversarially probed
  individually (the goal prioritized the hash-bound policy exception,
  then the decision record); they are covered by the same consumed-bytes
  digest derivation and the same generic anchor comparison, and their
  parse now also comes from the single consumed read.
- A path supplied twice under two labels is read once per label; each
  label's object and digest still come from that label's own consumed
  buffer (per-label same-bytes binding; both labels are anchor-checked
  against the final on-disk state).
- No physical power-loss or multi-host concurrency certification (as in
  R1–R3): interruption evidence is deterministic fault/monkeypatch
  injection plus fsync-call ordering proofs inherited unchanged.
- No R5 exists or is implied; any further hardening needs new
  independently reproduced evidence. The next package selected by the R3
  review after this conditional probe is Phase 7-C4-B (local operator
  rehearsal and activation state verification), to be planned in its own
  separately reviewed goal.
