### F1 — activation-store descendant containment (10 red)

| baseline layout | observed pristine-main behavior |
| --- | --- |
| `locks` → symlink to trap dir | apply **exit 0 `ACTIVATED`**; the flock lock file was created *inside the trap directory*; full activation completed |
| `journal` → symlink | apply exit 0; the intent journal JSON landed in the trap |
| `before-images` → symlink | apply exit 0; the content-addressed before-image landed in the trap |
| `receipts` → symlink | apply exit 0; the immutable receipt landed in the trap |
| `rollbacks` → symlink (rollback) | rollback exit 0 `ROLLED_BACK`; the rollback outcome landed in the trap |
| any of `locks`/`journal`/`receipts`/`before-images` as a regular file | exit 2 with the **raw unclassified** `[Errno 17] File exists: '.../journal'` (lock file already created first) |
| `rollbacks` as a regular file (rollback) | exit 2 raw `FileExistsError` **after the config had already been restored** — the restoration was not refused up front |

Conclusion: the C4-A root guard checked only the top-level activation root;
descendant publications followed symlinks out of the private store, exactly
as the review predicted.

### F2 — rollback audit outcome lost across an interrupted publication (6 red)

- Crash injected (library monkeypatch) exactly between the config
  restoration and the rollback-outcome publication: on-disk state proved the
  config held the exact prior bytes with **no** rollback outcome persisted.
- Retry of the same explicit rollback returned
  `{'status': 'ALREADY_RESTORED', 'outcome': None}` — the immutable audit
  artifact is **never** finalized; `rollbacks/` stays empty forever.
- `rollback_profile_activation` had no interruption hook (`TypeError:
  unexpected keyword argument 'fault_hook'`), so even deterministic
  before-replace interruption testing was impossible.
- A tampered *completed* outcome was accepted: the repeat rollback reported
  "already restored … zero mutation" without validating the corrupted
  outcome bytes, and the (c) case (prior bytes with no durable proof) was
  indistinguishable from a genuine completed rollback.

### F3 — advertised 'literal' apply command not executable (3 red)

- READY preview `apply_command_hint` contained the literal token `...`
  (baseline tokens: `['tve', 'evolution', 'activate-profile', '...', '--apply', …]`).
- With space-containing paths the unquoted `rollback_command` broke:
  `tve: error: unrecognized arguments: space dir/activation/receipts/….json
  space dir/activation`.

### Durability — directory-entry fsync ordering (1 red)

- Traced `os.fsync`/`os.replace` events across a full apply+rollback: the
  journal/before-image publications fsynced only the file body; **no parent
  directory fsync existed anywhere**, so a durable-intent-before-swap claim
  did not hold at the directory-entry level (test failed with
  `StopIteration` searching for the missing event).

## 3. Minimal implementation (this phase)

In `evolution/activation_execution.py` (+ additive CLI wiring in `cli.py`):

1. **Store containment** — `_guard_contained_dir`/`_guard_activation_store`
   lstat every existing component of `locks/`, `journal/`, `receipts/`,
   `before-images/` (apply) and `locks/`, `before-images/`, `rollbacks/`
   (rollback) below the already-verified activation root, refusing symlinks
   (`ACTIVATION_STORE_SYMLINK`), non-directories
   (`ACTIVATION_STORE_NOT_DIRECTORY`), unreadable state
   (`ACTIVATION_STORE_UNAVAILABLE`) and resolved escapes
   (`ACTIVATION_STORE_ESCAPE`), all **before the lock exists** — no lock
   file, journal, before-image, receipt or rollback byte can be created
   outside the private root. The read-only preview keeps its byte-exact
   semantics and does not fail on unused hostile descendants (pinned).
2. **Rollback audit recovery** — the additive immutable
   `ProfileActivationRollbackIntentV1`
   (`schemas/profile-activation-rollback-intent.schema.json`, drift-parity
   tested) is persisted create-only **before** the config restoration, and
   the unchanged outcome **after** it. A repeated explicit rollback that
   observes the prior bytes now distinguishes (a) genuine completion (valid
   outcome present → `ALREADY_RESTORED`, zero writes; a corrupt outcome is
   `ROLLBACK_OUTCOME_CORRUPT`, exit 2), (b) interrupted rollback (valid
   bound intent + still-hash-verified before-image → the outcome is
   finalized deterministically, `FINALIZED_AFTER_INTERRUPTED_RESTORE`, zero
   config mutation) and (c) prior bytes without durable proof (truthful
   `ALREADY_RESTORED`, **no fabricated outcome**). Tampered intents fail
   closed (`ROLLBACK_INTENT_CORRUPT` / `ROLLBACK_INTENT_MISMATCH`). Library
   fault points `rollback_intent_persisted` and `config_restored` were added
   for deterministic interruption tests (CLI never passes a hook).
3. **Runnable operator commands** — the CLI reconstructs the exact original
   `activate-profile` argument vector (`_activation_apply_argv`, every
   repeatable decision/evidence/inventory option) and the preview emits a
   complete `shlex.join`-quoted `apply_command_hint` (with
   `--apply --expected-plan-id … --expected-config-sha256 …` bound to the
   fresh identities); `build_rollback_command` and the apply-result payload
   are `shlex.join`-quoted too. No key material ever appears in a rendered
   command (pinned by test). The Chinese operations manual no longer
   presents an ellipsis-abbreviated example as literal.
4. **Directory-entry durability** — `_write_create_or_identical` now fsyncs
   the parent directory after the file body (and the activation root when a
   store subdirectory was just created), so journal/before-image/rollback
   intent publications that must precede a config swap are durable at the
   directory-entry level. The traced order is asserted in tests:
   journal + before-image (file + dir) → replace → config dir + receipt
   (file + dir); rollback intent (file + dir) → restore replace → outcome
   (file + dir).

Preserved unchanged: read-only default preview, explicit `--apply` +
fresh READY plan + expected-id binding, decision-record/evidence-bundle
strict association, byte-preserving single-value `[profiles].default` edit,
config CAS + exclusive lock, deterministic receipts/before-images and all
C4-A recovery classifications, all deterministic investment rules, and
every existing persisted contract field (the only schema change is the new
additive intent contract; `FAULT_POINTS` gained two library-only members).

## 5. Limitations and honest boundaries

- A short TOCTOU window remains between the store guard and the later
  `mkdir`/`open` (single-host, non-adversarial-race assumptions; same
  documented POSIX boundary class as the C4-A config CAS window).
- The fsync-order evidence is simulated-interruption/call-order proof, not a
  physical power-loss certification; cross-restart multi-file atomicity is
  still deliberately not claimed.
- In classification (a) the completed outcome is the authority; a corrupted
  leftover intent next to a valid outcome is not re-validated (the outcome
  proves the rollback ran). A corrupt *outcome* itself fails closed.
- The read-only preview intentionally does not guard unused store
  descendants (pinned semantics; its zero-write contract is what matters).
- Nothing in this phase approves, activates or defaults `strict-v2`; no
  real owner key, decision or policy exception exists anywhere in the tests.
