## 2. First live source: CNINFO official announcement query

Selection was based on bounded live probes (not the goal document's naming).
Four probe rounds (1–2 listings, short windows, page size ≤ 30, 15 s
timeout, 512 KiB response cap, no credential) inspected the current public
contract; raw responses are retained only under
`.tve-private/phase6b-validation/` and the existing private probe/cache
directories; none of these artifacts is tracked.

Verified contract:

- `POST https://www.cninfo.com.cn/new/information/topSearch/detailOfQuery`
  (`keyWord=<code>&maxSecNum=5&maxListNum=5`) resolves the CNINFO `orgId`
  for an A-share code (e.g. `600519 -> gssh0600519`, `000858 -> gssz0000858`).
- `POST https://www.cninfo.com.cn/new/hisAnnouncement/query` (form with
  `stock=<code>,<orgId>&seDate=<from>~<to>&pageSize<=30&pageNum=1`) returns
  metadata-only announcement rows: `announcementId`,
  `announcementTitle`, `announcementType` (`||`-joined 4–8-digit taxonomy
  codes; the last segment is the document-class leaf), `announcementTime`
  (UTC epoch milliseconds), `adjunctUrl`
  (`finalpage/<date>/<id>.PDF`), `secCode`, `secName`, `orgId`, plus
  `totalRecordNum`.
- The endpoint is unauthenticated and official-host only; HTTPS works.

Probe findings that shaped the boundary:

- `announcementTime` stamps scheduled disclosures at **Beijing midnight**
  (date-granular), while corrected re-releases carry a real time of day
  (e.g. `2026-04-30T18:20:27+08:00`).  A genuine midnight publication cannot
  be distinguished from date-only normalization, so the adapter derives only
  `published_date` and never fabricates a `published_at`.
- The request-level `category` filters are broad buckets, not exact document
  classes (`category_ndbg` returned Q1 documents and board resolutions);
  classification therefore uses only the per-document
  `announcementType` leaf code against a frozen, probe-verified table.
- Verified leaf codes: `010301` = annual report (600519 CN+EN FY2025 rows),
  `010303` = interim report (600519 H1-2026 report+summary; 000858 H1-2026
  report+summary and re-releases), `010305`/`010307` = Q1/Q3 reports
  (600519, 000858).  Q1/Q3 intentionally stay `INFORMATIONAL_DISCLOSURE`
  because the frozen Phase 6-A catalog has no quarterly type.

## 3. Implemented boundary

- `src/turtle_value_engine/providers/cninfo_disclosure.py`: bounded live
  CNINFO client implementing the frozen `FilingDiscoverySourceClient`
  contract — injectable `CninfoHttpTransport` protocol, stdlib
  `UrllibCninfoHttpTransport` with fixed timeout (default 15 s) and response
  byte cap (default 512 KiB), exactly two bounded POST requests per listing,
  credential-free, fail-closed org resolution (no active A-share match /
  delisted / ambiguous are hard errors), one-page acquisition that fails
  closed on truncation (`totalRecordNum > returned rows`), strict row
  validation (control characters, adjunct URL shape, taxonomy-code shape,
  integer timestamps), `published_date` derived from the Beijing calendar
  date of `announcementTime`.
- `src/turtle_value_engine/monitoring_acquisition/`: the Phase 6-B bridge
  package (deliberately outside `monitoring/`, whose frozen no-engine-import
  test is untouched):
  - `mapping.py`: deterministic `FilingRecord -> MonitoringEventV1` mapping.
    Frozen classification table
    `{(CNINFO, "010301"): ANNUAL_REPORT, (CNINFO, "010303"): INTERIM_REPORT}`;
    every other document class fails closed to `INFORMATIONAL_DISCLOSURE`
    with an explicit `unverified:informational` rule id and audit basis.
    `published_at` stays `None` (no fabricated precision).  `available_at`
    is the **last microsecond of the publication date on the official
    disclosure calendar (fixed UTC+08:00, no DST)** — the latest instant
    guaranteed to be at or after the true publication instant — never the
    local fetch clock.  `event_id` derives only from
    (source, listing, filing) identity.
  - `service.py`: provider-neutral acquisition orchestration.
    `network_allowed` defaults to `False` and is checked before the provider
    is called; `offline=True` replays the persisted raw cache record with no
    provider call; explicit `as_of` filters future-unavailable events from
    the batch; listing scope, window (≤ 366 days) and duplicate/limit
    bounds fail closed; raw provenance lands in the existing
    `RawResponseCache` envelope keyed by
    `filing-discovery-v1+cninfo-disclosure-v1` (the CNINFO client version is
    folded into the provider version so normalization changes can never
    replay an old cache entry under new rules).  The client also binds the
    resolved exchange plate and announcement `orgId` to the requested listing,
    and the library layer enforces the same 30-row source-page limit as the
    CLI.
- CLI: `tve watch acquire-events` with `--network deny|allow` (default
  deny), `--from-cache` offline replay, explicit `--source/--listing|
  --watchlist/--from/--to/--limit/--as-of/--cache-dir/--output/--workspace`,
  bounded `--timeout-seconds` (0, 60] and `--max-response-bytes`
  [1 KiB, 8 MiB].  The command never writes a `MonitoringWorkspace`; the
  committed-cursor window derivation is read-only.
- Config: additive non-secret `[monitoring] acquisition_cache_dir`
  (default `.tve-private/monitoring/provider-cache`) in
  `config/project.py`, `config/project.example.toml` and the in-package
  template.  `safe_summary()["monitoring"]` is unchanged (frozen Phase 6-A
  test).  No new persisted schema was introduced: the canonical batch is the
  existing `monitoring_event_batch_v1` artifact and raw provenance is the
  existing raw-cache envelope.
- No changes to `strict-v1`, deterministic calculation/gate modules, the
  Phase 6-A monitoring package, Dashboard code, Cloudflare deployment code
  or FQGate/Bridge lifecycles.  The provider-neutral interface keeps a
  future Bridge adapter additive; no Bridge semantics are hard-coded.
