materialization pair, the authoritative calibration workspace and all exact
frozen inputs. It resolves the R2 freeze/binding, reruns controlled-evolution
admission and B1 materialization in memory, and demands exact candidate bytes,
candidate hash, materialization ID and materialization content-hash equality
before projecting release bytes. A self-consistent pair from another honest
chain fails this comparison; the persisted pair grants no independent
authority.

uses the freshly reproduced candidate's complete rule payload, assigns a
deterministic target ID/name and restores status/description from the exact
base. The projection proves candidate/release rule-payload hash equality,
checks the full base/release scalar rule diff against the freshly reproduced
B1 `rule_changes`, and validates a deterministic `RuleProfile` YAML round
trip. The versioned release manifest binds exact source identities and hashes,
the intended `rules/strict-v2.yaml` path, release byte hash, rule-payload
hashes, metadata and rule changes. Its literals require human approval and
forbid automatic merge and application; no approval is recorded.

The existing B1-R1 two-stage no-overwrite publisher is reused: release
profile first, manifest last. Its provenance-aware rollback applies to normal
second-stage failure, and a process-death orphan has no authority. The
read-only resolver rejects missing, symlinked, tampered, hash-mismatched and
identity-mismatched bundles. Outputs under supplied inputs, active rules or
the workspace fail closed. Neither this path nor its tests construct a
network socket, provider, model, GitHub or transport client.
