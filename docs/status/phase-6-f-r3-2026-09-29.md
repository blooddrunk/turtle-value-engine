## What changed

All behavioral changes are in `scripts/monitoring_production_ops.py`, the new
`scripts/monitoring_credential_gate.py` (the dedicated non-secret
`ExecStartPre=` CLI), and twenty new deterministic regressions in
`tests/test_monitoring_production_ops.py` (one pre-existing fixture adapted
to the new verify semantics).

1. **Whole-file systemd-valid Unicode parity (review finding F1).** The one
   canonical parser now rejects, anywhere in the *decoded* file — comments
   included, not only values — `U+0000`, `U+FEFF`, the Unicode
   noncharacters `U+FDD0..U+FDEF`, and every code point whose low 16 bits are
   `FFFE`/`FFFF`. Strict UTF-8 decoding (which rejects encoded surrogates)
   stays in front of the scan. The R2 grammar is otherwise unchanged, so the
   invariant now reads: every file TVE calls canonical is valid under systemd
   `EnvironmentFile=` semantics, while TVE stays intentionally free to be
   narrower than systemd. Rejection reasons stay line/category based and
   never echo file content.
2. **One current-credential validation primitive (goal section 4).**
   `validate_current_credential(...)`/`CurrentCredentialState`/
   `current_credential_state(config)` combine the R1 metadata/path/type/mode
   boundary, the R2 canonical parsing with referenced-name completeness, and
   the R3 whole-file Unicode validation into a single operation whose parsed
   values exist only in process memory and whose
   `public_reason()`/`public_summary()` projections are value-free. Render,
   preflight, apply/converge, activate, verify, report, the live-proof
   delivery boundary, the recover-proof restart probe and the service
   pre-start gate all reuse it; no second EnvironmentFile parser exists. No
   raw value and no digest/HMAC/fingerprint derived from credential content
   is persisted anywhere — drift detection always re-reads the private file.
3. **Lifecycle drift gates (goal section 5, review finding F2).** When
   `delivery_enabled=true`: `apply`/`converge` revalidates the current
   credential immediately after the rendered-bytes check and before any
   install/daemon-reload/timer-enable/linger mutation (drift stops at
   `MANUAL_SECRET_REFERENCE_REQUIRED` with zero system mutation); `activate`
   revalidates before enabling/starting the timer (zero enable/start
   actions); `verify` adds the live `credential.current-contract` check plus
   an effective `service.prestart-gate` check, so a drifted credential is
   non-green even when units, timer and historical records are healthy;
   `report` embeds the secret-free `credential` summary and fails closed
   (`current-credential`) instead of emitting `PRODUCTION_DEPLOYED`,
   regardless of green historical records; `deactivate` remains deliberately
   credential-independent (safe stop/disable with a missing or invalid
   credential file).
4. **Service-execution pre-start gate (goal sections 6–7).** Every
   delivery-enabled rendered service unit now carries

   ```text
   ExecStartPre=<python> scripts/monitoring_credential_gate.py \
       --environment-file <private path> --production-root <private root> \
       --reference <name> [--reference <name> ...]
   ExecStart=<python> -m turtle_value_engine watch unattended-notify ... (unchanged)
   ```

   The gate CLI reuses the same primitive, sees the environment systemd
   prepared for the service (including the `EnvironmentFile=` injection),
   and compares every referenced value with the canonical parser's current
   in-memory value **byte-for-byte** (process-environment strings round-trip
   through `surrogateescape`, so the comparison is exact at the byte level
   and fails closed on invalid-UTF-8 environment content). Success requires
   metadata, canonicality, completeness and byte equality to all hold; any
   missing/mismatch/noncanonical/metadata failure exits nonzero with only
   status/category/reference names — so systemd never runs
   `unattended-notify` and no delivery dispatch slot is consumed. argv and
   output carry only non-secret paths/reference names; delivery-disabled
   units are byte-compatible with pre-R3 rendering (no gate, no
   `EnvironmentFile=`).
5. **Recover-proof restart check upgrade (goal section 8, review finding
   F3).** `cmd_recover_proof` now runs the *actual rendered gate command*
   through one bounded `systemd-run --wait --pipe --collect
   -p EnvironmentFile=...` transient service context
   (`_credential_resolution_probe`), proving canonicality **and** inherited
   byte equality instead of the previous non-empty-presence check. It stays
   extra evidence; the standing runtime guard is the rendered
   `ExecStartPre=` gate on every delivery service start.

## Deterministic regressions

Twenty new tests in `tests/test_monitoring_production_ops.py` (87 total in
the file; 67 pre-existing, one fixture adapted — the journal-redaction test
now uses a complete canonical credential file because verify is
legitimately non-green on an incomplete one):

1. `test_r3_ufeff_value_rejected` — U+FEFF in a value is rejected; the file
   contributes nothing to the effective scan/redaction set.
2. `test_r3_unicode_noncharacters_rejected` — `U+FDD0`, `U+FDEF`, `U+FFFF`,
   `U+1FFFF` and `U+10FFFF` values are rejected leak-free.
3. `test_r3_unicode_in_comment_rejected_whole_file` — systemd-invalid
   Unicode (including NUL) in comments rejects the whole file even when all
   assignments are canonical.
4. `test_r3_valid_multibyte_unicode_stays_canonical` — ordinary non-ASCII
   data (Chinese comment/values) is not collateral damage.
5. `test_r3_render_then_drift_apply_fails_before_any_mutation` — valid
   render, quoted drift, apply raises the marker with a parser-valid resume
   command and performs zero runner calls.
6. `test_r3_drift_after_apply_activate_authorizes_zero_actions` — drift
   after apply leaves activate with zero enable/start actions and no
   activation record.
7. `test_r3_verify_non_green_on_current_credential_drift` — verify fails on
   the live `credential.current-contract` check while `service.prestart-gate`
   still passes; the record leaks neither value.
8. `test_r3_report_not_production_deployed_on_current_credential_drift` —
   with every historical record green, drifted credentials keep the report
   away from `PRODUCTION_DEPLOYED` and add the secret-free credential
   summary.
9. `test_r3_deactivate_safe_with_invalid_then_missing_credential` — safe
   deactivation works with a broken and with a missing credential file.
10. `test_r3_delivery_unit_prestart_gate_before_unchanged_execstart` — the
    rendered unit carries only non-secret gate facts ahead of the unchanged
    `unattended-notify` ExecStart, and the rendered units pass the **real**
    `systemd-analyze verify`.
11. `test_r3_delivery_disabled_unit_has_no_gate` — the monitoring-only unit
    renders byte-identically to `render_service_unit` with no gate.
12. `test_r3_credential_gate_success_matches_inherited_bytes` — canonical
    file + byte-identical inherited values authorize (value-free output).
13. `test_r3_credential_gate_missing_inherited_reference_fails_leak_free`.
14. `test_r3_credential_gate_byte_mismatch_fails_without_either_value` —
    neither the file value nor the injected value appears in the output.
15. `test_r3_credential_gate_rejects_systemd_valid_but_noncanonical_drift` —
    a post-render quoted file (systemd-acceptable) with de-quoted inherited
    bytes is still rejected, and the failing gate structurally precedes the
    unchanged ExecStart.
16. `test_r3_credential_gate_metadata_boundary_enforced` — 0644 mode and a
    missing file are metadata failures.
17. `test_r3_credential_gate_cli_end_to_end` — the exact rendered argv runs
    standalone: success exits 0 with `CREDENTIAL_GATE_OK`, quoted drift
    exits 2 with `CREDENTIAL_GATE_REJECTED`, value-free on both streams.
18. `test_r3_recover_proof_probe_requires_byte_equality` — the upgraded
    restart probe is green only on byte equality; a present-but-different
    injected value (which the pre-R3 presence check accepted) fails.
19. `test_r3_dual_source_scan_semantics_preserved` — R1 dual-source
    scanning/redaction stays intact, and a Unicode-broken file contributes
    no file values while the harness-side value keeps coverage.
20. `test_r3_transient_systemd_execstartpre_gate_proof` — a **real systemd
    user-manager transient service** with fake sentinels: the healthy
    canonical file passes the gate and the (fake) notify command runs;
    after the owner drifts the file to quoted syntax, the gate fails
    value-free and the notify sentinel is never created. Skips cleanly on
    hosts without a reachable user manager.

## Secret handling

No real secret was requested, pasted, printed or persisted at any point.
All regression sentinels are fake `.invalid` values living only inside the
test process and temporary files; the transient/standalone systemd proofs
used fake sentinels and `--collect` transient units that leave no manager
state. The real production deployment is monitoring-only
(`delivery_enabled=false`, no environment file configured), so no credential
source existed to read; the R3 boundary was exercised exclusively through
temporary fixtures. No secret value or credential-derived
hash/digest/HMAC/fingerprint is persisted in any unit, JSON, report or
other artifact — drift detection re-reads the private file in memory.
Tracked, generated and test-output artifacts contain secret references,
line-number reasons, paths, categories and statuses only.
