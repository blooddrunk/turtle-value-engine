## 3. Implementation (commit `b228103a96d1e17e9670172b72b2853c6e374f05`)

`evolution/activation_execution.py` plus CLI wiring (`tve evolution
activate-profile`, `tve evolution rollback-activation`), four checked-in
drift-parity schemas, and `docs/operations/profile-activation-executor.md`
(Chinese-first, literal commands).

- **Preview (default, read-only)**: derives the fresh plan + executor
  association check + the exact byte-preserving `[profiles].default` edit and
  unified diff + intended before-image/receipt paths + literal apply hint and
  rollback command, and writes nothing (not even the activation root);
  `preview_state` `READY_FOR_APPLY` / `BLOCKED` with the union of plan and
  executor blockers; `original_config_sha256` binds the exact config bytes.
- **Apply (explicit opt-in)**: requires BOTH `--apply` and the freshly
  previewed `--expected-plan-id` + `--expected-config-sha256`; the exclusive
  per-config `flock` (non-blocking; contention = exit 3 `ACTIVATION_BUSY`
  with zero work) is taken before anything else; the entire plan is
  re-derived from authoritative current inputs inside the lock (never a
  saved plan JSON or earlier READY); the edit substitutes exactly the one
  `default` scalar preserving every other byte (validated by re-parsing:
  only `profiles.default` may differ semantically), with classified refusals
  for missing/ambiguous/multi-line/non-string defaults; the mutation order
  is intent journal → content-addressed before-image → same-directory
  temp + fsync + CAS re-read + `os.replace` + dir fsync → deterministic
  create-only receipt (all publications `O_CREAT|O_EXCL` with byte-identical
  idempotence).
- **Realistic crash consistency** (documented, not over-claimed): config
  replacement is atomic; journal/before-image/receipt publication is not one
  multi-file transaction. Interrupted states are classified by name from
  observable disk state: `COMPLETED_ALREADY` (receipt present, config at
  activated hash — explicit no-op), `FINALIZED_AFTER_INTERRUPTED_REPLACE`
  (config replaced, receipt finalized from the journal, zero further
  mutation), `ACTIVATED_RESUMED` (replace never happened, idempotent resume
  with identical deterministic identities), `ACTIVATION_CONFIG_DIVERGED`
  (foreign change after the journal; before-image preserved, fail-closed),
  `ACTIVATION_INTENT_CONFLICT` (a different unfinished intent; manual
  resolution), `ACTIVATION_CONFIG_UNSTABLE` /
  `ACTIVATION_CONFIG_CHANGED_DURING_APPLY` (config bytes moved after preview
  or during the critical section; staged write discarded, never clobbered),
  `PLAN_ID_MISMATCH`.
- **Target/path guards**: symlinked and non-regular targets, and resolved-path
  aliasing into checked-in repository trees (`config/`, `rules/`, `docs/`,
  `src/`, `tests/`, `schemas/`, …) are refused for both the config target and
  the activation root — the checked-in template, rule profiles and release
  artifacts can never be the mutation target under any alias; already-target
  configs surface the explicit `DEFAULT_ALREADY_TARGET` no-op; output paths
  are guarded create-only and may not overlap inputs.
- **Rollback (separately invoked)**: validates the receipt (deterministic id
  + content hash), verifies the before-image's content-addressed hash and
  prior-default content, and restores the exact prior bytes by the same
  staged atomic replace only when the config still holds the receipt's
  activated bytes — any intervening change (even a comment) is
  `ROLLBACK_PRECONDITION_VIOLATED` with zero clobbering; a repeat rollback is
  `ALREADY_RESTORED` (exit 0, zero writes); an immutable rollback outcome is
  persisted; monitoring/notification replay and historical-artifact rewrites
  remain the fixed C2 exclusions.

## 5. Limitations and boundaries

- The executor mutates exactly one operator-supplied private TOML's
  `[profiles].default`; it never touches rules, release artifacts, the
  checked-in template, watchlists, monitoring state or historical artifacts.
- Cross-restart multi-file atomicity is deliberately not claimed: the
  recovery table in the operations doc is the contract. A foreign writer
  that ignores the executor's lock is caught by the CAS re-read before
  replace and by the journal classification afterwards; a TOCTOU window of
  a few instructions between the CAS read and `os.replace` remains an honest
  POSIX boundary (the lock covers all well-behaved TVE callers).
- Journals, before-images, receipts and rollback outcomes accumulate
  immutably in the private activation root; they are local audit artifacts
  and never enter Git. Cleanup of old receipts is deliberately absent
  (retention is an owner decision).
- The rollback restores configuration bytes only; it does not and cannot
  undo analyses already produced under the activated profile (the fixed C2
  exclusions), which the operations doc states explicitly.
- The read-only planner's preserved acceptance of a same-id
  different-content-hash record remains pinned as planner semantics; any
  future tightening belongs to the planner's own review, not the executor.
