## 4. M6-B closure and exact verification

M6-B implements the explicit-input, read-only boundary described by the active
goal:

- `SurfaceRegistry` and `SurfaceReadService` validate explicit in-memory
  snapshots or repeatable explicit paths, reject empty/tampered/duplicate
  registrations, keep deterministic ordering/filtering, and never discover
  workspace/raw-store files;
- the optional `api` extra contains lazy FastAPI/uvicorn/httpx dependencies;
- the API exposes only `GET /healthz`, `GET /v1/surfaces` and
  `GET /v1/surfaces/{surface_id}`, with stable error codes, ETag/304 handling,
  no mutation routes, and loopback-first serving;
- `tve surface serve` defaults to `127.0.0.1`; non-loopback binding requires
  `--allow-non-loopback`;

  smoke: it waits for `/healthz`, reads a known surface and verifies its
