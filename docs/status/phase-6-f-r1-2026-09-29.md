## What changed in `scripts/monitoring_production_ops.py`

1. **Effective secret-source model (finding F1).** New
   `effective_secret_values()` merges, per referenced secret name only, the
   values resolvable from the harness process environment **and** from the
   configured private systemd `EnvironmentFile`; when the two sources carry
   different values for one reference, both are kept. `_effective_secret_scan_map()`
   flattens them into one value set for `scan_bytes_for_secrets`/`redact_text`
   (a second value gets derived scan bookkeeping keys such as `NAME~2`; hit
   reports stay value-free and public `secret_references_checked` lists plain
   reference names). Resolved values remain memory-only. All eight scan/redaction
   call sites were converted in a complete audit: preflight tracked-repository
   scanning, verify journal redaction, `_service_wake` journal redaction, the
   D3 payload secret scan, the live-proof production-artifact scan and its
   serialized-report guard, the recover-proof serialized-report guard, and the
   report production-artifact scan plus serialized-report guard.
2. **Private `EnvironmentFile` contract (finding F2).** New
   `validate_delivery_environment_file()` machine-checks, when delivery is
   enabled: regular file, resolved path inside the production private root
   (symlink/`..` escapes rejected), and owner-only permissions (any group/world
   bit rejected; `0600` documented normal form). `ProductionConfigV1` now also
   rejects at parse time a `delivery_environment_file` that is not lexically
   inside `production_root`. The harness never chmods or rewrites the owner's
   file and reports only path/permission metadata. Missing, unreadable or
   insecure credentials stop at the existing precise
   `MANUAL_SECRET_REFERENCE_REQUIRED` boundary in preflight, render and the
   live-proof delivery step.
3. **Exact manual-resume commands (finding F3).**
   `windows_bootstrap_marker_payload(config, production_config_path)` and
   `ensure_linger(..., production_config_path=...)` now build their resume
   commands from the real production-config path through the canonical
   `_resume_command()` helper (the `<config>` placeholders and the trailing
   prose that broke runnability are gone; the Windows-bootstrap timing note
   moved into `machine_verifiable_success`). The missing-EnvironmentFile
   render boundary now emits `_resume_command(path, "render")` — argument order
   `--production-config <path> render` round-trips through `_build_parser()`
   — instead of the invalid `render --production-config ...` form. The
   `cmd_apply` sudo boundary and the live-proof delivery boundary already used
   the canonical helper and were re-verified unchanged.
