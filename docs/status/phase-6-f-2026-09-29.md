## Capability boundary (the single marker, non-blocking)

`WINDOWS_HOST_BOOTSTRAP_UNPROVEN` — recorded with all six disclosure items.
Linux-side evidence (systemd PID 1, `/etc/wsl.conf` `[boot] systemd=true`,
`Linger=yes`) proves the user manager and the production timer persist and
run whenever the WSL distro runs, including after manager re-exec and
timer/system restarts. Nothing readable from inside the distro proves the
Windows host auto-starts this distro after a Windows reboot, so the
persistence claim is exactly narrowed to *"persistent while the WSL
distro/user manager is running"* and Windows-reboot autostart is explicitly
not claimed. The marker records the optional human action (an owner-created
Windows logon task running `wsl.exe -d <DistroName>`), the exact resume
command, the machine-verifiable success condition (a future topology probe
reading a Windows-side autostart registration through interop flips the
flag) and the exact remainder left unverified. Per goal §11 this narrows
the claim without blocking closure on a WSL host; no physical reboot was
required or performed.
