## 6. Remaining limitations

- No real authenticated owner-provenance source exists yet: with no
  injected verifier the production CLI can never emit a READY plan (by
  design). The injected-verifier READY path is reachable only through the
  library boundary by a hosting test/process; a future real verifier (C3)
  must be separately selected with immutable captured evidence and offline
  replay.
- The plan-time reverification binds the verifier's evidence hash to the
  canonical serialization of the *decision record* (the authoritative
  artifact available at plan time); the original unsigned submission bytes
  remain bound through the record's `provenance.source_content_sha256`, which
  reverification requires to be present.
- `OWNER_AUTHORITY_REVERIFICATION_ERRORED:<cause>` embeds a bounded
  verifier error description; it is a blocker, never an acceptance.
- The `os.open`/`Path.exists` interleaving hooks in the concurrency tests
  are in-process orchestrations; no real multi-process barrier is claimed
  (the exclusive-open semantics are kernel-enforced and the same pattern is
  already exercised two-process in D2B-R1 elsewhere in the suite).
