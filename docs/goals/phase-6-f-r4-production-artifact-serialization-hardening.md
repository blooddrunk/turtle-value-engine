## 1. Objective

Make every accepted non-secret production owner input survive generated-artifact serialization with exact semantics.

The required invariant is:

typed owner input -> generated bytes -> real parser / systemd manager -> effective value

For execution-critical systemd fields and the generated production project TOML, the effective value must equal the typed value exactly. No accepted path or string may be silently split, expanded, reinterpreted or corrupted by shell-oriented quoting, systemd percent/environment expansion, or TOML string escapes.

## 2. Frozen boundaries

Do not change or reinterpret:

- Phase 6-A/6-B/6-C event, acquisition or re-analysis semantics;
- D1 cycle/outbox identity;
- D2A/R1 lease/recovery semantics;
- D2B/R1/R2 delivery identity, retry or receipt semantics;
- D3/R1 read-only projection;
- Phase 6-E/6-F cadence, convergence or accepted production topology;
- R1/R2/R3 credential metadata, canonical parsing, Unicode and service-time byte-equality semantics;
- strict-v1, valuation, gates, adjustments and investment rules.

Do not add Phase 7, Bridge/FQGate integration, a new provider, a new notification vendor, brokerage/trading behavior, M4-D/M4-E/M2-D, Windows host autostart or a remote secret manager.

Do not enable real notification delivery as part of R4.

## 3. Systemd-native serialization contract

Replace shell-oriented or raw interpolation on execution-critical systemd values with one explicit systemd serialization layer.

At minimum cover:

- ExecStartPre gate argv;
- ExecStart argv;
- EnvironmentFile path;
- WorkingDirectory path;
- any directly related path-bearing unit field whose parser can perform quoting or specifier expansion.

Requirements:

1. Do not use shlex.join() as the unit-file serializer. shlex may remain appropriate for human shell resume commands; that is a separate boundary.
2. Serialize every Exec argument according to systemd command-line grammar, with quoting that wraps a whole item and with systemd-valid escaping.
3. Owner data containing a literal dollar sign must not become systemd environment-variable expansion.
4. Owner data containing a literal percent sign must not become a systemd specifier. Literal percent must survive manager parsing as percent.
5. Spaces, single quotes, double quotes, backslashes, semicolons, hashes and ordinary non-ASCII characters in accepted path arguments must round-trip exactly.
6. Preserve the existing command identity and argument ordering for ordinary inputs.
7. Do not weaken R3: the credential gate must still run before the unchanged unattended-notify command and must still receive only non-secret path/reference facts.

on_calendar is intentionally a systemd calendar expression and is not a literal-path field. Do not escape away its intended systemd syntax.

## 4. EnvironmentFile and credential-gate parity

The private credential source remains the R1/R2/R3 EnvironmentFile contract.

R4 must prove that the path delivered to all three consumers is identical:

- the unit EnvironmentFile directive;
- the R3 gate --environment-file argv;
- validate_current_credential() / current_credential_state().

A valid private path containing supported parser-significant characters must not be interpreted as another path by systemd.

The credential file contents, values and canonical grammar are out of scope except for preservation tests. No secret value or secret-derived digest/fingerprint may enter the unit or generated artifacts.

## 5. Generated project TOML serialization

render_project_config() must use a real TOML-safe string serialization boundary rather than direct raw interpolation for owner-provided strings.

At minimum prove exact parse round-trip for:

- watchlist_path;
- monitoring_workspace_root;
- delivery_root;
- delivery destination/reference strings that are emitted as TOML strings;
- telegram_chat_id when emitted;
- any other ProductionConfigV1 string inserted into the generated project TOML.

A generated project config is accepted only if Python tomllib can parse it and the parsed values exactly equal the typed owner inputs.

Do not solve this by silently forbidding ordinary filesystem characters unless systemd/TOML itself cannot represent them or the repository has an explicit portability reason. Prefer correct serialization.

## 6. Effective-manager verification

Strengthen production verify so it does not treat textual substring presence as proof of the effective ExecStartPre/ExecStart contract.

For delivery-enabled units, verify must prove the manager-effective pre-start argv corresponds exactly to credential_gate_argv(config), including argument boundaries and literal owner paths.

For both delivery modes, verify must prove the manager-effective main ExecStart argv equals the intended argv.

Use a structural manager/API representation or another deterministic normalization that compares argv elements, not a substring such as expected_gate in ExecStartPre.

Keep verify non-mutating.

## 7. Required deterministic regressions

Add focused tests that fail on pre-R4 main 7ee61df709b7eee3e45c5d24a989e5de8c613f52 and pass only after R4.

At minimum cover:

1. systemd Exec argument round-trip with a path containing a space;
2. a single quote;
3. a double quote;
4. a backslash;
5. a literal dollar-sign sequence that resembles an environment variable;
6. a literal percent sequence that resembles a valid systemd specifier such as %n;
7. semicolon/hash characters as ordinary argument data where allowed;
8. ordinary non-ASCII path text;
9. delivery-enabled ExecStartPre effective argv equals credential_gate_argv() exactly;
10. delivery-enabled main ExecStart effective argv remains the existing unattended-notify command with exact argument boundaries;
11. delivery-disabled main ExecStart remains the existing unattended-run command;
12. EnvironmentFile path with supported parser-significant characters resolves to the exact intended file and the R3 gate still passes with fake sentinels;
13. generated project TOML parses with tomllib for quote/backslash/parser-significant path inputs and every parsed value equals the typed input;
14. existing ordinary production rendering stays byte-compatible where no escaping is required;
15. R3 credential drift/Unicode/gate tests remain green.

Include fail-on-main evidence with the exact baseline SHA and test selection result.

## 8. Real parser / manager proof

All deterministic tests must be offline and safe.

Run systemd-analyze verify on rendered edge-character units, not only the reference deployment files.

If the execution host has a reachable systemd user manager, automatically run a bounded transient proof using only temporary files and fake sentinels. It must demonstrate that the manager launches a helper with the exact intended argv for representative space/quote/dollar/percent paths and that the R3 pre-start gate still blocks a drifted credential before the fake main command.

Skip cleanly only when the user manager is genuinely unavailable. Do not ask the owner to run the proof manually.
