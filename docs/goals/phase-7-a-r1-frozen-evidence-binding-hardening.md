## 1. Objective

Make `READY_FOR_HUMAN_REVIEW` mean that the evaluation is bound to the exact frozen
calibration evidence that existed when calibration ran, not merely to a same-id manifest or
to an observation set that happens to reproduce the same derived scores.

Also make the persisted evaluation contract reject incomplete or non-canonical READY
artifacts before any later Phase 7 consumer can trust them.

## 2. Frozen boundaries

Preserve all of the following:

- `rules/strict-v1.yaml` bytes and semantics;
- Phase 5 deterministic calibration scoring and chronological split semantics;
- `CandidateProfileProposal` proposal-only / no-automatic-application semantics;
- Phase 7-A's offline/non-network evaluator boundary;
- no profile materialization, `strict-v2`, PR creation/merge or human-approval recording;
- no provider/source expansion, Bridge/FQGate integration, notification-vendor expansion,
  Windows bootstrap or brokerage/trading work.

Do not add an economic performance threshold or decide whether a candidate is a better
investment rule.

## 3. Additive calibration evidence binding

Introduce a versioned immutable persisted binding contract (suggested name
`CalibrationEvidenceBindingV1`) with a checked-in JSON Schema and deterministic
`content_sha256`.

At minimum bind:

- deterministic binding id;
- `manifest_id`;
- exact `manifest_content_sha256`;
- `experiment_id`;
- exact `experiment_content_sha256`;
- exact canonical `observations_content_sha256`;
- observation count;
- base profile id;
- exact base profile SHA-256;
- proposal id and canonical proposal payload SHA-256 if naturally available at the same
  boundary.

The binding must be generated by the calibration/freeze path while the exact manifest,
experiment and observation rows are simultaneously available. It must not be invented
inside `evaluate_controlled_evolution()` from the evaluator's own supplied inputs.

Prefer an additive sidecar/envelope or new helper over mutating the existing persisted
`CalibrationExperiment` v1 contract in place. Existing Phase 5 artifacts must remain
readable.

Expose a deterministic library path and an additive CLI/workspace persistence path so a
normal calibration can produce the binding without manual JSON assembly.

## 4. Evaluation hardening

Extend the controlled-evolution evaluator so `READY_FOR_HUMAN_REVIEW` requires a valid
prior evidence binding.

At minimum:

1. supplied manifest id and content hash must equal the binding;
2. supplied experiment id and content hash must equal the binding;
3. supplied canonical observation-set hash/count must equal the binding;
4. supplied base-profile id/hash must equal the binding;
5. proposal identity/hash must agree if the binding records them;
6. missing binding must fail closed — it may produce a BLOCKED dossier for compatibility,
   but it must never produce READY;
7. keep all existing 7-A checks and canonical scorer/holdout replay.

A same-id manifest with different valid bytes/content must be BLOCKED. A change only to
`CalibrationObservation.source_hash` must be BLOCKED even when every calibration score and
holdout result remains unchanged.

## 5. Persisted dossier semantic integrity

Harden `ControlledEvolutionEvaluationV1` itself.

Requirements:

- define one canonical required-check set for this contract version;
- a READY dossier must contain exactly that required set, with no omission, duplicate or
  unknown substitution;
- canonical check ordering should be deterministic if ordering contributes to the persisted
  bytes;
- `evaluation_id` must be recomputed/validated from the bound identities rather than being
  accepted as arbitrary text;
- `content_sha256` remains a deterministic hash over the final persisted payload;
- schema parity tests must cover the hardened constraints.

If the additional evidence-binding admission check changes the canonical check count, update
the architecture/closure docs honestly; do not keep the historical "thirteen" wording as if
nothing changed.
